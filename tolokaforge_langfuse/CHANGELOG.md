# Changelog

All notable changes to the `tolokaforge-langfuse` wheel are documented here. The file is
regenerated by `cz bump` from the Conventional Commits scoped to this project (see
`docs/RELEASING.md`, "Cutting a tolokaforge-langfuse release").

## Unreleased

### Feat

- the **write-once layout** for a receiver whose observations are append-only (Langfuse v4 in its
  default write mode): the family is detected once per run by capability
  (`options.langfuse.server_api`, `auto` by default), the live rows become declared previews under
  the id contract's new preview kinds and a preview root parented to the final root, the bundle's
  projection is converted to OTLP spans by the new engine-free `otlp_spans` module and written
  once with the root last, the manifest rides on that root, the scores keep the ingestion route
  and carry the grading's own timestamp, and a trace whose root can no longer come gets one
  minimal error root at run end. New receipt counters: `langfuse.previews_sent`,
  `langfuse.final_observations_sent`, `langfuse.error_roots_sent`, plus `server_api` in
  `details`, and `langfuse.roots_unconfirmed` for a root the exporter posted and could not
  confirm (no second root is written for it: the receiver may hold the first). On that family the
  exporter also posts each batch once, because a retried batch the receiver already wrote would be
  a duplicate it cannot delete. A v3 receiver keeps its wire traffic: neither the direct ingestion
  header nor the single-post exporter is used there (plugin API 4)

- the trace-level mirror of the primary grading is joined by a categorical `primary_grading` score
  naming the grading it mirrors, both marked `scope: primary` in the score metadata. On a receiver
  whose trace metadata cannot be corrected after its single write, that pair is the current
  verdict, and a dashboard filters on the marker; on a v3 receiver it is the same answer written
  twice, which costs one score
- **on both families**, every score now carries the grading's own timestamp, and every trace the
  `primary_grading` score above: two deliberate changes to what a v3 receiver stores, so that a
  score is dated by the grading rather than by the upload and the current verdict is readable
  without the trace metadata

- the Langfuse trial observer leaves the engine: the OTLP exporter, the trial-end projection of a
  persisted trial bundle, the attachment step, the gradings pass, the deployment profile and the
  model-name resolution ship as this wheel, found by the engine through the
  `tolokaforge.trial_observers` entry-point group (ADR-0047, packaging amendment)
- one trace vocabulary for both producers (`vocabulary.py`, imported by the offline uploader):
  a closed prefix list with a producer / caller split, the engine's value lists, tags derived
  from the bundle and the model-name normalizer (`model_generation`, `model_tier`,
  `model_variant`, `model_size`, `model_stage`, `model_snapshot`, `reasoning_mode`,
  `reasoning_effort`, `reasoning_budget`, `route` = the configured provider), the default environment rule; the deployment
  profile becomes schema 2 (value lists, required prefixes, derivations, metadata keys,
  derived-tag groups) and is the one file the offline uploader reads too; the launcher's inputs
  are checked at run start; the native `version` of a live trace names this package
