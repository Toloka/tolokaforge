# Changelog

All notable changes to this project are documented in this file.

## Unreleased

### Changed

- **runner**: **a run refuses to start against a pack whose grading cannot be graded, naming every offending task.** Before it schedules the first trial — and at `tolokaforge prepare`, so a distributed enqueue is rejected once rather than by every worker identically — the orchestrator makes one pass over every selected task and puts its grading block through the same predicate `tolokaforge validate` applies. That covers the authoring rules checked against the task's tools *and* every migration rejection the typed grading blocks carry: a removed `state_checks.env_assertions` / `db_hash_check` key, and the free-text `rubric` / `output_schema` / per-task `model_ref` shapes, were previously only rejected while artifacts were written — the last phase of a trial the author had already paid for (#696). The abort lists **every** offending task rather than the first, because an author fixing a run's packs wants the list. The pass resolves each task's wire description once and keeps it, so the trials that follow reuse it; a task naming an adapter the host has not installed is rejected in the same pass. `evaluation.grading_validation.fail_on` (a new optional block, default `advisory`) names the least severe finding class that is fatal — `advisory` fails on errors and advisories, `error` on errors alone — and what the gate could not check is logged and fails nothing under either. An existing run config is unaffected — but a run whose pack was already mis-authored now aborts at startup instead of grading with a check that silently decided nothing. Note that `evaluation` is `extra="ignore"`, so a misspelled *block* name (`grading_validaton:`) is dropped without a word and the defaults stand; the block's own fields are `extra="forbid"` (#679, #696)

- **grading**: **a grading block that names a tool the task does not have is now an authoring error, heard before a trial is paid for.** Three shapes were reproduced end to end and all three charge the author's typo to the agent or to nobody: `tool: { equals: http_reqest }` in a `present` matcher scores the component `0.0` with `present is unmatched: match selected no event`, byte-identical to a genuine agent failure; the same typo under `absent` scores `1.0` against a timeline where the tool *was* called, so the check can never fail; and an uncompilable `regex` raises `re.error` out of the evaluator at grade time, which core lets propagate and the runner folds into a failed grade response — losing the trial, not the constraint. `tolokaforge validate` and (from the pre-run gate) a run now check the block against the tools the task gives its actors: **errors** for a tool name outside the declared set (in `trace_checks` matchers and in `transcript_rules.tool_expectations`), for an argument name outside the properties of a tool whose schema forbids extras, for a pattern that does not compile, and for `state_checks.hash.expected_state_hash` declared under a falsy `hash.enabled` — a confirmed silent no-op, since both substrates read the flag before the hash; the flag is read for truth rather than for `true`, because core branches on its truthiness and the runner coerces it, so `enabled: 1` grades and loads; an **advisory** for an argument name outside the properties of a tool whose schema *permits* extras, which an MCP schema always does, so hard-failing would enforce a claim the schema does not make. What the schema cannot answer is reported as **unchecked and never fails anything** — a separate channel, not a third severity, so the gate has no false-reject mode: nothing reads it to decide whether to raise, and the CLI prints it beside the task because a gate that could check nothing must not read as a clean bill of health. An `args` path is checked at its **first segment only** (`json.q` on `http_request` is checked at `json` and stops, because `json`'s schema declares no properties); descending further is **#765**. A tool named by `regex` rather than by `equals` / `in_` produces no finding — a pattern names a set, not a token. Measured on the shipped corpus: all **57** packs under `examples/**` and `tests/data/tasks/**` that ship a `grading.yaml` produce **zero errors and zero advisories**, so nothing that grades today stops loading (#679)

- **grading**: **an ordering constraint written over one matcher is rejected at load unless some trajectory can decide it.** Both sides of a `before` carrying the same matcher, or an `absent_before` / `absent_between` forbidding the very events its window is measured from, is usually a constant — nothing follows the last of a matched set and nothing precedes the first — so the check passes or fails every trial whatever the agent did, which is the same defect as an unsatisfiable count bound. Measured cell by cell against the evaluator at zero to four matching calls: of the 38 quantifier combinations these shapes admit, **ten** still say something and are kept — `before` and `immediately_before` with `left ∈ {first, any}` and `right ∈ {last, any}` ("the events occur at least twice", except `immediately_before` `first` before `last`, which reads exactly twice), `absent_before` anchored `last` ("the events occur once"), and `absent_between` from `first` to `last` ("exactly twice"). Of the other 28, twenty-seven are false at every trajectory; the twenty-eighth — `absent_before` forbidding its own anchor, anchored `first` — is **not** a constant but decides exactly what `present` decides, so it is rejected as `present` written the long way round rather than as a check no agent can move. All 28 are load errors naming the shape that would express the intent. No shipped pack writes one (#679)

- **cli**: **`tolokaforge validate` exits non-zero, and validates the task a run would load.** The command counted failures, printed `N valid, M invalid` and returned `0` regardless — so the four CI steps that run it (`ci.yml:126, 198, 302` and `release-gate.yml:55`) could never fail a build, and every "fails `validate`" contract in the docs was unenforceable. It now exits `1` when any matched task fails to load, after printing the same per-task lines and summary, and **`1` when the glob matches no file at all**, naming the pattern: a pattern selecting nothing validates nothing, which is exactly the shape a CI glob drifts into (#764). **A script or CI step that treated a failing `validate` as success now fails.** Measured on the shipped corpus: `examples/**/task.yaml` → 28 valid / 2 invalid, exit `1` (the two are the `terminal_bench` pair, which declare no `task_id` / `description`); both CI globs — `examples/native/*/dataset/**/task.yaml` (23/0) and `tests/data/tasks/wire_probes/dataset/**/task.yaml` (20/0) — stay clean and exit `0`, so no lane reddens. Each task now also loads **under its enclosing project**: `validate` resolves the `project.yaml` above the task and layers its `task_defaults` beneath the task's own fields, the same layering the orchestrator applies, so the object validated is the one the run loads rather than a project-less reading of it — measured, that changes the effective config of 18 of the 28 example tasks and breaks none. `project.default_environment` is deliberately *not* layered: it binds into a `TaskDescription`'s `EnvironmentManifest` and `validate` builds none. A `project.yaml` that fails to load fails the tasks beneath it, naming the project file, and the rest of the glob is still validated. **`make validate` gains a directory guard** — task packs are cloned separately, so with `TASKS_DIR` (default `tasks`) absent *and* `TASKS_GLOB` still the default derived from it, the target prints a skip reason and exits `0` instead of failing on an empty glob. Naming a `TASKS_GLOB` runs it whatever `TASKS_DIR` holds, so pointing the target at a pack elsewhere is never silently skipped. The dev MCP's `validate_tasks` answers for the same default and skips the same case (#679)

### Fix

- **deps**: **the `mcp` dependency is upper-bounded on its major, so every MCP-backed task's tool calls work inside the runner container again.** `core/tools_interface.py` imports `mcp.server.fastmcp`, the one module the harness needs from that package, and `mcp` 2.x does not have it — FastMCP moved. The declared range was `mcp>=0.1.0`, and the runner image installs the built wheel with **pip**, resolving that range itself rather than reading `uv.lock` — so the image picked up `mcp` 2.0.0 while the workspace venv stayed on the locked `1.28.1`. The failure mode was as bad as the pin was loose: the MCP server subprocess died at import inside the container and **every** tool call of every task declaring an `mcp_server.py` came back `Tool error: RuntimeError: MCP server closed connection`, so an agent burned its whole turn budget on failing tools and the trial graded `0.0` — a full-price run that measured nothing, with the harness itself at fault. Reproduced on `examples/native/native_shared_domain`: three trials, `tool_calls=5`, every call failed, `avg_score_micro=0.0`. Now `mcp>=1.0,<2`, in `[project.dependencies]` and in the dev group, and a rebuilt runner image resolves `1.29.0` and imports `FastMCP`. **Anyone with an image built from an unpinned resolution must rebuild it** (`make docker-build-core`). `docs/TROUBLESHOOTING.md` § "Every Tool Call Fails: MCP server closed connection" carries the symptom, the pip-versus-`uv.lock` cause and the rebuild, and `docs/RUNNER.md` § Engine / image version lock names the image's own dependency resolution as a second, unversioned skew no gate sees. The dev MCP server's own `pyproject.toml` gains the same bound, its `server.py` importing `mcp.server.fastmcp` too (#683, #794)

- **grading**: **an attempt whose grading refuses is counted and keeps its bundle instead of vanishing from the run.** `RunnerRPCTrialGrader.grade` raises `GradingFailedError` when `GradeTrial` returns no verdict; the conductor's grading phase catches it, records the reason on the new `Trajectory.grading_error`, and lets the trial finish its normal path. The attempt reaches `total_trials` and `measured_trials`, stays out of `scored_trials`, and its `status` / `termination_reason` still describe how the trial itself ended — grading's failure rewrites neither. Previously the exception escaped the conductor, so `_write_artifacts` never ran and the trajectory never reached the run's results: **a two-trial task with one grading failure reported `total_trials: 1` and a perfect `success_rate: 1.0`, and wrote no `trials/` directory at all.** The same task now reports `total_trials: 2`, `measured_trials: 2`, `scored_trials: 1`, `avg_score: 1.0`, `success_rate: 0.5`, `pass@1: 0.5` — every rate deflates visibly and boundedly, never inflates. **The attempt is also no longer retried**: it terminates normally, and retryability reads the trajectory's own status and reason. A grading failure a second attempt would have got past is therefore recorded ungradeable on the first — the price of never fabricating a verdict and never counting one attempt twice. Two compatibility surfaces move together: `trajectory.yaml` gains a `grading_error` key (`null` on every trial that graded or was correctly not graded), and the per-trial bundle stamp `metrics.yaml.schema_version` goes **2 → 3**. A v2 consumer could read an absent `grade.yaml` as "the infrastructure aborted this trial"; under v3 that inference is wrong, because an ungradeable trial has none either — `grading_error` is the discriminator. `Trajectory` also rejects a value carrying both `grade` and `grading_error` at construction and `model_validate`; previously written aggregates and bundles keep their values and are stale by design (#720)

- **metrics**: **an ungradeable trial is now visible as *ours*, with its own class, its own count and its own row.** `TrialOutcomeClass` gains a fourth member, `UNGRADEABLE`, which `classify_trial_outcome` reads from `Trajectory.grading_error` **before** the `(status, termination_reason)` pair and unconditionally — a refusal is typed evidence that *we* failed, while exclusion from the denominator is earned by typed evidence that the provider or the substrate killed the trial, so no termination reason buys a refused trial out of the numbers. Three compatibility surfaces move together. `per_task_metrics.json` / `aggregate.json` / `metadata_slices.json` gain an **`ungradeable`** count, sitting inside `measured_trials` exactly as `harness_errors` does; a trial is classified once, so `0 <= harness_errors + ungradeable <= measured_trials`. `outcomes_by_reason` gains a **new key form**: an ungradeable trial's row is keyed `ungradeable_<reason>` (`ungradeable_agent_done` for the common case) rather than by the reason alone, because it terminates the way a graded trial does — measured, one graded and one ungradeable `agent_done` trial shared a single row of `count: 2` whose `class` was whichever trial the loop saw last, which destroyed the split the row exists to preserve. And `aggregate.json`'s `schema_version` goes **2 → 3**: for one and the same run a v2 file and a v3 file report different `total_trials` and different rates (measured: 1 vs 2, `success_rate` 1.0 vs 0.5), which is the identical different-denominators situation that earned the 1 → 2 bump, and a consumer switching exhaustively on `class` now meets a fourth value. **Rates move downward** on any run that hit a grading failure — the attempt is a non-pass, not an absence — so a dashboard that dips on the day this lands is reporting a grading regression it was previously blind to. Previously written aggregates keep their values and are stale by design; the stamp makes the generation machine-detectable. `failure_attribution.json` also stops blaming the model for our grading bug: such a trial is `failure_class: grading_failure`, `deterministic: true`, with the cause as evidence, where it previously fell through to `model_reasoning` at `confidence: 0.5` (#720)

- **dx**: **the live panel tells the truth about a trial that was never graded.** A completed trial's row in the left pane now carries its verdict — `pass`, `fail`, or `n/a` — three pairwise-distinct renderings, so a trial grading could not judge no longer reads as one the agent passed. Previously the pane rendered `✓` for **every** completed trial whatever the verdict, and stored `binary_pass` and `score` without ever drawing them: an ungraded, non-retryable trial looked like a pass, and the fabricated `binary_pass=False` the orchestrator handed the display for any trial with no grade was wrong and invisible at once. The call site now passes what the trajectory actually holds, and `RunDisplayEvents.trial_completed` / `LiveRunDisplay.trial_completed` widen `binary_pass: bool` → `bool | None` to carry it. `RunDisplayEvents` is a documented Protocol seam ([ADR-0019](docs/adr/0019-front-end-plugin-namespace.md)): the widening is source-compatible for callers and **not** for a third-party implementation that narrows the parameter to `bool` — such an implementation must widen its own signature. The in-tree `_NullRunDisplayEvents` takes `**_` and is unaffected. Closes #714 (#720)

- **runtime**: materialisation now bind-mounts the host docker socket (`/var/run/docker.sock`) into the runner service whenever a task routes a shipped tool through the compose variant (`tools.agent.<tool>.service`), on the same trigger that bakes the docker CLI into the runner image. The compose-variant `bash_session` / `str_replace_editor` wrappers `docker exec` from the runner into a sibling service; the CLI was present but the socket was not, so every exec failed to reach the daemon and the tool lifecycle surfaced `bash session failed to become ready` at trial-register time. Both per-trial and shared task-declared-stack backends inject the mount; the injection is idempotent, so a pack that already declares the socket volume is left unchanged
- **runner**: the persistent `bash_session` shell no longer recurses to a `RecursionError` when its backing process cannot stay alive. `_PtyBashSession.run` treated an empty read (the shell pipe closing — the process exited) as a timeout, routing a dead session into `_terminate_runaway`; for the compose engine (`docker exec` into a service container) that path reopens the exec and re-runs the sentinel, which reads EOF again and recurses without bound (one forked `docker exec` per level) whenever the target container is not running — surfacing at trial start as `Tool lifecycle start failed: maximum recursion depth exceeded`. EOF is now handled distinctly from a timeout: the session is closed and the failure surfaces cleanly (e.g. `open` raises `bash session failed to become ready`)
- **runner-client**: `GrpcRunnerClient.health_check` now accepts both `healthy` and `degraded` runner statuses (per `docs/GRPC_PROTOCOL.md` § HealthCheck) as reachable-for-connect purposes. The prior strict `status == "healthy"` check made every trial pack without a `db-service` fail the 30-attempt connect loop even though the runner's `HealthCheck` RPC was successfully answering. Only `unhealthy` and `RpcError` remain as fail states (#801)

### Feat

- **grading**: **one shipped rubric criterion is narrowed against recorded evidence, its veto preserved on both halves, and scores on that pack are not comparable across the change.** `native_shared_domain`'s duplicate-check pair — `add_note_duplicate_check_gated` and `add_note_duplicate_check_policy` — graded a two-conjunct policy with one `required: true` criterion: *`list_notes` ran before `add_note`* **and** *the user was warned about the near-duplicate*. The ordering conjunct is now the shared `severity: gate` constraint `the_notes_were_listed_before_the_note_was_added`, and `checked_duplicates_first` keeps the warning conjunct alone — **still `kind: binary`, `required: true`**, so the trial-level veto survives on both halves and the pack's difficulty does not move sideways. `combine.weights` goes from `{llm_judge: 1.0}` to **`{llm_judge: 0.7, trace_checks: 0.3}`** at an unchanged `pass_threshold: 0.75`, so neither component reaches the threshold alone and a passing trial did both halves; a `trace_checks` weight is mandatory rather than optional, because a scored component with no declared weight is dropped core-side and folded in at an invented `1.0` runner-side (#744). The judge's `reference` stops asking for the ordering half outright — a reference still describing it would have the judge charging a conjunct the gate already owns, making the narrow a text change and nothing else. **Both arms move in one commit**, because the pooled evidence rests on their rubric and constraints being byte-identical, and both carry a byte-identical `migration.yaml` declaring `mode: narrowed`, the pre-migration criterion text in `was`, `residual: {kind: text}` naming what the judge still reads, the post-migration `combine_weights`, and `evidence` of 17 observations at κ `1.0`. The consequence: `tolokaforge reconcile --source tests/data/migration_corpora/notes_duplicate_check` now exits **`0`** on the **default `--packs examples/`** — 17 observations, accuracy `1.0`, κ `1.0`, `no_counter_evidence` — so the migration's evidence is re-verified in CI against the pack a reviewer reads rather than against a fixture, and editing the shipped constraint reds. Under the map the declaration carries, the counterfactual reports the five judge-vetoed trials moving `0.000 → 0.700` in trial score with the judge component `0.000 → 1.000` — that column being the **bound of a full retirement** rather than the narrow's own effect, since it drops the criterion from the judge's side outright where the narrow keeps it `required: true`, and the narrowed text has no recorded label for anything to compute the narrow's figure from — the twelve met trials unchanged at `1.000`, and the **pass rate unchanged at 12/17 → 12/17** — because the veto the judge held passes to the trace gate, which fails exactly the five trials whose criterion the judge failed. Three standing scenarios are locked over the shipped pack: listing and warning scores `1.0` and passes; listing without warning fails the judge's required gate **alone** at `0.3`; never listing fails the trace gate **alone** at `0.7` — an attribution the single conjoined criterion could not make, and one `binary_pass` alone cannot see. **Nothing here says the bar chose `narrowed` over `retired`, and nothing can**: zero disagreements satisfies both conditions, so the mode is the author's recorded judgment and the `residual` claim is its justification. Fixture packs under `tests/data/migration_packs/` stay as the negative-case home, declaring the same narrow with **no** `combine_weights` — the only way the counterfactual's *source* is measurable, since a report folding under the pack's own map would be indistinguishable once the shipped pack holds the declared one. The not-comparable notice follows the precedent of #680, #681 and #778: a pack whose grading gains a component grades a different question than it did, and a stored score from before the change is not a baseline for one after it (#683, #744)

- **grading**: **a new `tolokaforge reconcile` command decides a declared rubric migration against recorded judge verdicts, at zero cost, and refuses it rather than reporting a scalar.** For every criterion a pack's `migration.yaml` declares, it recomputes the constraints the entry is `by` over each recorded trial's timeline — through the one production trace evaluator — and joins that verdict to the judge's own recorded `grade.yaml.criterion_results` verdict for the criterion. It spends nothing (no agent, no environment, no judge; measured — no `litellm` / `openai` / `anthropic` module and no judge module enters `sys.modules` on import) and **never edits a pack or a bundle**, only its own report under `<source>/reconcile/<replay_id>/reconcile_report.yaml`. The bar has **three conditions and no magic number**. *Evidence*: Cohen's κ over the joined labels must be **defined** — a corpus with no label variation has total chance agreement, so κ is `None` while accuracy reads `1.0`, and that is `insufficient_evidence`, never a pass; there is no threshold on κ's value. *Direction*, because κ cannot see it — measured, κ is identical at `0.720` (n=7) for a permissive and a strict disagreement of the same count: `retired` tolerates no unacknowledged disagreement either way, while `narrowed` tolerates the **permissive** ones (judge not-met, constraint passed) that are a narrow's expected shape and reports each per trial with the judge's own justification. *Acknowledgement*: a disagreement is waived only by naming its trial and a reason, and a waiver whose disagreement is gone — the trial agrees now, or is not under `--source` — is **refused**, because a standing waiver would waive the next disagreement on that trial unread. The passing verdict is named **`no_counter_evidence`**, not `supported`: it says no trial in this corpus contradicted the claim over N observations, and it is the only verdict exit `0` means. Every entry's report carries the **2×2 contingency table** beside κ, required rather than optional, because a corpus whose mass sits in one cell is visibly a designed experiment that an accuracy of `1.0` hides. Nothing in the report ranks or compares modes and nothing can — zero disagreements satisfies `retired`'s condition *and* `narrowed`'s, so the mode is the author's recorded judgment — which is locked by **set-equality over the report model's field names** rather than by prose, an absence-of-phrase assertion over free text passing on every implementation. The declared `was` block is verified against the rubric **each contributing bundle recorded**, not against the pack: the pack holds only the post-migration state (for a `retired` criterion, nothing at all), so the bundle is the only surviving record of the pre-migration shape, and this is what closes the bypass an author opens by changing the declaration and the pack in one commit. It also catches a corpus **regenerated after the migration**, whose evidence would silently re-base onto the state the migration produced; because the fix is counter-intuitive the refusal says so in words — "the corpus records the post-migration rubric; evidence for a migration must come from bundles recorded before it". Two bundles recording different shapes for one criterion is refused naming both, mirroring replay's existing rule for two bundles claiming one task with different blocks. **`evidence.observations` and `evidence.kappa` are read rather than merely recorded**: they are what a reviewer reads instead of re-running the command, so a run measuring **more** observations than the declaration claims, or reaching the declared count at a different κ, is refused. The rule is a bound rather than an equality because pointing `--source` at part of the declared corpus is a documented diagnostic — it is how each half of the two-arm corpus is shown to be the other's falsifier — so a run measuring *fewer* observations says nothing; κ is compared at the three decimals the report prints, which is the number an author copies. The residue is stated in the docs rather than hidden: a declaration over-*counting* its own corpus is indistinguishable from a subset run. The constraint block is resolved **from the pack** the bundle's `task_id` names — `--packs`, repeatable, default `examples/` — and there is deliberately **no** `--constraints`-style flag: measured, a valid one-line edit to the shipped constraint flips all five verdicts over the frozen corpus and reds the CI lock, where a pinned fixture would make the guard decorative. A `task_id` resolving in none of the searched roots or in more than one is an error naming the id and the roots. A trial contributes no observation when its recorded rubric lacks the criterion, its `judge_status` is anything but `completed` (an errored judge reached no verdict; folding it in as not-met would manufacture agreement with a failing constraint), its `criterion_results` is absent or empty, it holds no verdict for the criterion, or a named constraint was undecided — each reported **with its reason**, so a shrinking denominator is visible. Labels come only from the original bundle and never from a replay grade, whose deterministic components and gates are absent (#775). `reconcile` is a separate command from `retrace` because `retrace`'s exit code is reserved for the readability of a corpus — a non-discriminating constraint and a disagreement with the recorded grade both exit `0` there, deliberately — and a gate on a decision cannot live there without changing that contract. Ships with the **first committed judge-labelled corpus**: seventeen recorded trials under `tests/data/migration_corpora/notes_duplicate_check/`, trimmed to the files the differential reads and committed in plain git, in two halves that are the two arms of one experiment. `not_met/` holds the five recorded `notes_add_note_duplicate_check_gated` trials, judge not-met and constraint-failed on every one; `met/` holds twelve trials of a **new sibling testcase**, `notes_add_note_duplicate_check_policy`, judge met and constraint-passed on every one. Over `not_met/` alone the entry reports accuracy `1.0`, κ `null`, all five observations in one cell and `insufficient_evidence`; over the union it reports **17 observations, accuracy `1.0`, κ `1.0`**, a 2×2 with twelve met/passed and five not-met/failed and nothing off the agreeing diagonal, and `no_counter_evidence` — exit `0`. Each half is the other's falsifier and both verdicts are locked, because κ defined is the condition the bar cannot be reached without. The sibling is byte-identical to the gated testcase in rubric, weights, initial state, user message and backstory: **the independent variable is one paragraph of system prompt**, and buying the second label cost **`$0.032325`** of measured API spend across the whole session — fifteen trials at an unchanged cheap agent (`openai/gpt-4o-mini`), three of them discarded at curation — of which **`$0.021335`** is the twelve committed ones (agent `$0.005222` plus judge `$0.016113`, summed from their own `metrics.yaml` and `grade.yaml`). Both figures are **lower bounds**: the user simulator runs `claude-sonnet-4-6` and no recorded field attributes its cost at all (#329). The stronger-agent lever was measured *failed* — two of the five `not_met/` trials ran `anthropic/claude-sonnet-4-6` as the agent and skipped `list_notes` anyway, which is why the prompt was the only lever left. Because a task-level `system_prompt` is a **path** that *replaces* the inherited one on merge rather than extending it, the sibling ships its own `system_prompt.md` carrying `_shared/system_prompt.md` **verbatim** with the policy paragraph **appended**, and a canonical guard asserts containment with `startswith` — which an append satisfies and an interleave cannot — so editing the shared prompt reds instead of quietly making the two arms incomparable. The corpus is then the honest ceiling of this bar and the docs say so: a met half produced by a prompt instructing exactly what the constraint measures cannot distinguish "the constraint matches the criterion" from "the agents did what they were told". **Two frozen corpus measurements move with the new testcase**: `tolokaforge validate` over `examples/**/task.yaml` is now **29 valid / 2 invalid** (exit `1`, the two still the `terminal_bench` pair), and the authoring gate's clean sweep is now **58** packs under `examples/**` and `tests/data/tasks/**`, still zero errors and zero advisories. Beside the evidence, every entry carries a **counterfactual**: per trial, the judge component and the trial `(score, binary_pass)` **before and after** the migration, beside both `combine.weights` maps and the **veto set before and after** — the last because a `required` criterion frees no score share at all, so whatever a declared map moves for one is the author's own rebalance rather than the conversion's arithmetic, and a weight-shift-only report would be silent about what the conversion itself moves. The veto set is **mode-aware** where the component and score columns are not: a `narrowed` criterion stays in the rubric and stays `required: true`, so its *after* set carries **both** it and the trace gate — two vetoes over one policy, which is the shipped narrow's whole shape and which an after-set omitting the kept one would misreport as a veto lost. A `retired` criterion is gone, so its veto goes; a `candidate`'s counterfactual projects the retirement it is a candidate *for*. It is folded under **the map the entry declares, never the map the pack holds today**, which is the post-migration state a reviewer is being asked to judge; where the entry declares none — permitted only for a criterion carrying no score share — the map that trial was graded under is used, nothing having been freed to move. The *after* columns are recomposed by the same function the runner folds a live trial through: the runner-side judge-gate zeroing and trial-verdict forcing, previously inline in `runner/service.py`, are now one `compose_runner_trial_verdict` in `tolokaforge/runner/grading.py` that wraps `combine_grade_components` (whose signature is unchanged) and applies both gates around it. Verified on all seventeen committed bundles: the extracted composition reproduces each recorded `grade.yaml` verdict exactly, and on the five the judge vetoed, dropping the gate zeroing makes every one report a judge component of `1.0` against a recorded `0.0`, since required criteria are excluded from the weighted average. Over the union the narrow moves no trial verdict — pass rate **12/17 → 12/17** — for a stated reason rather than by luck: the veto the judge held passes to the trace gate, which fails exactly the five trials whose criterion the judge failed. That check runs at reconcile time, not only in a test — a trial whose recorded verdict the composition cannot reproduce is listed under `unrecomputed_trials` with the divergence spelled out and carries no before/after row, because a composition that cannot reproduce what the runner already decided says nothing about what the migration would decide. **Nothing reads the counterfactual** — no verdict, no exit code, no refusal — and that is deliberate: gating on it would infer an unbounded safety property from a finite corpus, the inference this bar exists to refuse. It is what makes the freed-share rule's mandatory declaration reviewable instead of merely present: an entry declaring the identity map on a criterion the judge scored below `1.0` reports the judge component **rising**, the accepted residual made visible rather than trusted. New `docs/RUBRIC_MIGRATION.md`; `docs/CLI.md`, `docs/TRACE_REPLAY.md` and `docs/JUDGE_REPLAY.md` cross-link it (#683)

- **grading**: **a task directory may declare what its rubric is migrating into trace checks, in a new optional `migration.yaml` sidecar, and the two hazards that migration carries are refused at authoring time.** The file is optional and no existing pack changes behaviour — nothing about grading reads it. It records, per rubric criterion, the constraint ids that are a `candidate` for it / have `narrowed` it / have `retired` it, the criterion's pre-migration shape, the post-migration `combine.weights` map, and the corpus of recorded judge verdicts the claim rests on, so the claim can be checked against those verdicts rather than asserted. It is a **sidecar rather than a `grading.yaml` key** because `GradingConfig` is `extra="ignore"`, so a `migration:` key there is silently dropped, and making it a real key needs a `GRADING_KEYS` manifest entry, whose every `KeyKind` describes score production — which this metadata must never do. Every rule is an **error naming what to write instead**, raised by `tolokaforge validate` and **deliberately not** by the pre-run gate: the file cannot affect a grade, so a run must not abort on authoring metadata. Two of the rules are the reason the file exists. The **veto rule**: a `narrowed` / `retired` entry on a `required: true` criterion may only name **shared** constraints carrying `severity: gate`, because a required criterion is a trial-level veto carrying zero score share — measured, retiring one leaves the judge score bit-identical at `0.7333` and only `gate_failed` changes — so a route-scoped gate (escapable inside `alternatives`) or a scored constraint is a fraction of a component where a veto was, and nothing downstream reveals the loss. The **freed-share rule**: a `narrowed` / `retired` entry on a criterion that is *not* required must declare `combine_weights`, because a scored criterion's weight sits in the judge component's denominator, so removing one the agent failed makes the judge **more generous** — measured at `+0.667` on `cache_debug`'s `explains_mechanism`, on a trial that scored it `0.0`. A `candidate` entry is charged neither rule: it replaces nothing, so the criterion keeps both its veto and its share whatever it names, which is what both shipped candidacies are. Because the veto rule reads the author's `was`, a `narrowed` entry's `was` is **cross-checked against the criterion the pack still holds**: `was.required` and `was.kind` must equal the current ones, since an unchecked `was.required: false` escapes the veto rule outright and a flipped `kind` makes the recorded evidence incomparable with what the judge scores afterwards. **`was.weight` is deliberately free** — a criterion that now asks less may legitimately weigh less, and requiring a match would refuse a correct migration while adding nothing against the escape. A `retired` entry's `was` is not cross-checked, the criterion being gone from the pack, so no load-time source holds its pre-migration shape. `residual` is a small `extra="forbid"` model `{kind: none | text, reason: str}` rather than a string, because no one scalar carries both a sentinel and free text — measured with `yaml.safe_load`, `none` / `None` / `NONE` all parse to non-empty **strings** while `null` / `~` parse to `None`, so a `narrowed` entry writing `residual: none` would pass a non-empty check and a `retired` entry meaning exactly "nothing remains" would fail one. `retired` requires `kind: none` and a non-empty reason and `narrowed` requires `kind: text`, in both directions, because which of the two a pack means is the **author's recorded judgment** and not something evidence decides. A `candidate` carries **no** residual at all, which makes `residual`'s presence and kind a total function of `mode` — absent, `text`, `none` — so a reader can tell what an entry claims from its mode alone. `docs/TASKS.md` § Task Layout and `docs/GRADING.md` § Trace Checks document the file, and `docs/REFERENCE.md` § Configuration Schemas carries its annotated block beside `run.yaml` / `task.yaml` / `grading.yaml` (#683)

- **cli**: **`tolokaforge retrace` re-checks a recorded run's `trace_checks` constraints, and spends nothing doing it.** It rebuilds each discovered bundle's trial event timeline from the bundle's own artifacts and scores a `trace_checks` block against it through the one production evaluator — no agent, no environment service, no judge, so no container starts and no token is bought. It is a **new** command in the `Runs` group; no existing command's flags, output or exit codes change. A directory is a replay bundle iff it directly holds `task.yaml` + `trajectory.yaml` — not `grade.yaml`, because a trial is worth re-checking whether or not it was ever graded — and `trace_replay` (its own output) and `replays` (judge replay's) are **reserved directory names**: a bundle beneath either, at any depth under `--source`, is not discovered, so the two commands never read each other's output — at the deliberate cost, documented rather than discovered, that a task named either would hide its own trials. `--constraints <file>` **replaces** each bundle's block wholesale rather than merging (two constraint lists folded together assert something neither was written to assert, and partial satisfaction across declared routes is already a grading bug), and the supplied block goes through the same `inspect_grading_authoring` a pack meets before a run, checked against the tool set each bundle *recorded*: an **error** aborts the batch naming the file and the defect **before any trial is re-checked**, because a misspelled tool name is one defect in one file and replayed it would arrive as a corpus of trials that all failed a constraint selecting nothing. A constraint declared inside an alternative route is measured only over the trials that route won, so it still gets a row and every row carries `route` beside `trials_evaluated`, with the denominator stated once. `trials_labelled` and `agreed_with_recorded_pass` put each recomputed verdict beside the verdict the live run recorded for **that same constraint**, joined by id off `grade.yaml`'s `trace_check_results` — never against the trial-level `binary_pass`, which would count a disagreement whenever a trial failed for reasons no one constraint is responsible for; a trial where either side is undecided, or whose bundle recorded no verdict for the id, is not labelled at all, and the trial-level pass is reported per trial instead. Evidence to read, not a check that must hold. A `--replay-id` is held to a single directory name, since the read-only guarantee is scoped to `<source>/trace_replay/<id>/` and a separator or `..` in it would name a tree outside `--source`. **A non-discriminating constraint exits `0`**, deliberately, as does a disagreement with the recorded grade — both are results, and a CI job must not go red because a corpus turned out to be uninformative; an unreadable bundle, an override the gate refuses, and a `--source` holding no bundle at all exit `1`. - **grading**: **`trace_checks` grades genuinely alternative routes, and a constraint can be a check that must hold rather than a share of the score.** Two new authorable keys on the `trace_checks` block. **`alternatives`** declares **two or more** named routes (`id`, `description`, its own `constraints`); each is scored over its **decision set** — the shared `constraints` plus that route's own, normalised within the set, so routes need no weights against each other — and the component is the **highest-scoring route's**, with the winner recorded. A tie goes to a route whose gate shut and otherwise to the first declared: preferring the gated route can only ever shut a component and never rescue one, and without it the trial's verdict would turn on which of two equal-scoring routes the author wrote first. This is what `any_of` structurally cannot express: `any_of: [A_step1, B_step1]` beside `any_of: [A_step2, B_step2]` passes an agent that did half of each, which is neither route. A **single** path is the flat form written the long way round and is a load error, as are a block declaring neither key, an id repeated anywhere in the block's one id space (paths and every constraint list share it, because an id is how the grade and the pre-run gate address a sub-check), a `weight` beside a gate, `on_missing: pass` beside a gate (it would open the gate on every trial whose anchor matched nothing, and a gate carries no share for the policy to save a second charge on), and a route whose decision set has no scored member while another route's does (a constant `1.0` standing in front of every scored sibling — that gate belongs in the shared `constraints`). **`severity: gate`** marks a constraint that is not scored and must hold: it enters neither the numerator nor the denominator of the weighted fraction, a tripped gate takes the component to `0.0` and **fails the trial on both substrates** independent of `pass_threshold`, and the grade names the gates that shut and the route the score came from. The core engine had no gate path at all before this — the rubric judge is runner-only — so this is the first gate it honours. **This is the judge's required-criterion gate reused exactly**, not a second semantics: excluded from the average, the failed-id list, the component zeroing, the forced `binary_pass`, and the all-gates collapse (`1.0` when every gate held, `0.0` otherwise) — which is **not** conditional on `alternatives`, since a flat block of nothing but gates reaches it too. `tests/canonical/test_gate_semantics_parity.py` drives `aggregate_rubric` and the trace fold through one shared answer table and fails naming the cell if they disagree; no shared helper is extracted, because the trace fold's weighted fraction is held to one division and no branch while the judge's must raise on a non-positive denominator (**#771**). **An undecided gate trips it.** Undecided is not a pass in the agent's favour anywhere in this vocabulary, and a gate that opened there would be *weaker* than the scored constraint it replaced. The consequence is sharpest on a bundle re-graded without its tool-call record, which cannot read `status` or `executor`, so a gate reading either fails every re-graded trial — write gates over evidence the message view carries and keep `status` / `executor` for scored constraints, where the same limit costs a weight rather than the trial. **A path gate is a *process* gate**: it constrains how *that* route must be walked and is consulted only on the route that won, so **a gate that must hold whatever route the agent took belongs in shared `constraints`**, where it is in every decision set. The argmax deliberately runs over every route including gated ones, so a route cannot escape its own gate by scoring at or below a clean sibling; the escape that remains one level up — trip a route's gate *and* sandbag that route so a clean one strictly outscores it — is real, ships documented, and is pinned by a characterisation test rather than claimed closed. **Wire**: `TraceConstraintResult` gains `string severity = 7`, and `Grade` gains `TraceChecksSummary trace_checks_summary = 11` — `winning_path`, `gate_failed`, `failed_gate_ids`, and one `TracePathResult` per declared route carrying that route's own score, never zeroed, so the max the component took is auditable from `grade.yaml` alone. Both fields are written on every graded trial, matching their unconditionally-serialised sibling `trace_check_results`. **These are new keys on `extra="forbid"` runner-side models, so an engine of this release requires a runner image built from it for any pack declaring either** — `RegisterTrial` rejects an older image — while core's `extra="ignore"` means an older engine ignores them. `cache_debug` is the only shipped pack that declares them (see the entry below; scores on that pack are not comparable across the change) and no other pack changes verdict. - **grading**: **a `trace_checks` constraint can correlate arguments across matchers — it binds a value out of one event and requires, elsewhere in the same constraint, that another event's field equal or contain it.** Every predicate before this compared a field against a value written into the YAML, so *this call's id equals that call's id* had to be written as one constraint per concrete identifier, which does not generalise across task instances and silently stops covering whatever the author did not enumerate. A constraint's new optional **`bind`** declares the matcher whose events supply candidate values (`match`), the names extracted out of each (`values`: one `field` per name addressing `tool`, `text`, `result` or an `args.<dotted path>` on the kind `bind.match` selects, with an optional `pattern` narrowing it to exactly one regex capture), and **`on_unbound`**. `ValuePredicate` gains **`equals_binding`** and **`contains_binding`**, taking `TRACE_PREDICATE_OPERATORS` from fifteen to **seventeen**: both name a value rather than writing one and delegate to the same `operator.eq` / `contains` their literal siblings use, so **a bound constraint with exactly one candidate scores byte-identically to the same constraint with that value written out** — locked on score, verdict, message and matched positions. `bind` is a field of the **constraint** rather than of a matcher, a deliberate deviation from the issue's "a matcher can bind": the `require` tree becomes a function of an environment, so routes, gates, Kleene, quantifiers, `within`, `on_missing`, the weighted fold and the accounted-keys ledger all compose unchanged, and a reference reaching across a route boundary needs no rule of its own — it is the unbound-name load error. No new constraint kind (the vocabulary stays at **ten**) and **no `.proto` change**: the block already crosses as JSON inside the trial spec, and the failing values ride the result message that already crosses. **Quantification over the candidate set is universal, and the two alternatives were rejected against measured rows rather than argued.** Binding at the write over `read X`, `write X`, `write Y` gives candidates `X`, `Y` scoring pass and fail, so an **existential** reading clears an agent that wrote a record it never read because a *different* write happened to be correlated — "silently stops covering what the author did not enumerate", one level up. **First-match** is deterministic but not invariant: binding at the read, `read X`, `read Y`, `write X` passes where `read Y`, `read X`, `write X` fails, two orderings of one set of actions the constraint says nothing about. The universal reading is invariant under every permutation of the binder's events, which is what makes the *reported* binding reproducible too — the failure names the **set** of values that failed (`; failed under (rec='Y')`, appended to the kind's own sentence) and a set has nothing to choose. **Candidates are distinct values, not events**, two being the same only when every name's value is equal *and* of the same type, so `True` and `1` are two candidates and ten calls naming one record are one reading of the `require` tree and one reported value rather than ten. **The binder site is the direction of the implication** — binding at the write says "every record written was read first", binding at the read says "every record read was later written" — `negate` inside a bound constraint reads `∀v ¬P(v)`, "no candidate satisfies", because quantification is outermost, and `within` restricts the binder like every other matcher in the constraint. **The candidate set is itself three-valued, and reading only its two ends over-fails.** The binder resolves through the same machinery every predicate does, so it has undecidable events of its own, and a `field: result` extraction on a call the trial recorded no outcome for is a candidate whose *value* the trial does not carry — where an `args` path the call simply did not pass binds nothing at all, absent value against absent evidence, the same distinction a predicate over the field draws. The readings compared are the **empty** one, `D ∪ {u}` for **each** undecidable `u`, and `D ∪ U`; the singletons are not redundant beside the two ends, because with `D` empty the empty reading is `on_unbound` rather than a vacuous pass, so at `D = {}`, `U = {u₀ holds, u₁ fails}`, `on_unbound: fail` both ends read *fail* where the completion `{u₀}` holds. Brute-forced against all `2^|U|` subsets in both `on_unbound` modes, the shipped enumeration agrees on **every** cell — 1040 of them at `|D| ≤ 2`, `|U| ≤ 3`, each driven through the real evaluator over a real trajectory rather than a stubbed verdict — where the two-end shortcut disagrees on 22 of those and on 86 of the 3146 cells one undecidable candidate wider. It is the same over-fail a `count` bound guards against by reading its whole reachable interval rather than its endpoints, met one level up. **`on_unbound` decides the trial whose binder selected nothing**, the case the universal reading calls vacuously true, and defaults to **`fail`**: zero writes means the agent did not do the task. `on_unbound: pass` is the opt-in for a constraint whose empty case genuinely holds — an agent that quoted no figure invented none, and failing it charges a second time for a gap another check already charges — and beside `severity: gate` it is a load error, since a gate carries no share for that second charge to be avoided on. It is a policy over **decidable** evidence and stays separate from the Kleene handling above. **A constraint whose binder yielded no assignment files the kinds nested under its `require` tree as a SKIP** rather than leaving them unaccounted: a scored key the config populates and the ledger cannot account for fails the whole `GradeTrialResponse`, and walking the *config* to fill the gap instead would report a kind as evaluated that nothing evaluated. The tree's own top-level kind is `EVALUATED`, because the constraint takes a verdict under it whatever the binder yielded — `on_unbound` decides which — and a grade that failed the trial on a kind must not also report it skipped. A kind any other constraint in the same block scored stays `EVALUATED` too. **Every malformed binding is a load error naming what to write instead**: a `bind` declaring no `values`; a bound name no predicate in the constraint references; `equals_binding` / `contains_binding` naming a name the constraint does not bind; a reference inside `bind.match` to a name that binder itself produces; an extraction whose head segment is outside the fields the selected kind carries; an extraction over `status` or `executor`, closed vocabularies of a handful of members an `equals` literal already names; a `pattern` capturing zero or several groups; `on_unbound: pass` beside a gate; and — **#717 extended** — an extraction reading `result` without `status: { equals: success }` on the binder's `match`, because the landed rule fires on a `result` *predicate*, which a binder carries none of, while a failed call's result text is not identical on the two substrates and a value bound out of it propagates that difference into every reference. **`tolokaforge validate` reaches inside bindings**: the authoring gate's matcher walk covers `constraint.bind` as well as `constraint.require`, so a misspelled tool name, an argument address outside the tool's declared properties and an uncompilable pattern are all reported inside a binder, addressed `trace_checks.<id>.bind.match…` / `.bind.values.<name>.…`, in a route's binder too. **The bound value's type is load-bearing, and both tiers reject rather than warn.** `contains` compares two strings as substrings and falls back to equality for any other pair, so `contains("http://api/deliveries/4021", 4021)` is `False`, and `equals` over a string and a non-string is false outright — so **either** binding operator between a text field and a value bound out of an integer argument is false on **every** trajectory, indistinguishable from a genuine agent failure. At evaluation it is a named failure saying the comparison was not made, naming the binding, its value, its type, the operator that could not make it and the two correct ways to write the intent; at `tolokaforge validate` it is an **error** where the tool's schema types the extraction and forbids extras, an **advisory** where the schema permits them, and **unchecked** where no schema resolved, where the path runs below its first segment (#765), or where the property writes no `type` — there the evaluation-time failure is the whole backstop, and the docs say so rather than implying the gate covers everything. Neither correct form is ever flagged: `equals_binding` on an `args` predicate compares two natively-typed values, and a `pattern` capture is always `str`. Three adjacent never-true classes the gate still leaves unflagged are filed as **#781**, a constraint may declare only one binder (**#777**, filed with the measured cost of widening it), and `cache_debug`'s result-capture patterns assume the request tool's repr rendering with no guard (**#782**). **Wire and parity**: `trace_checks.constraints.bind` joins the key manifest as a `CONFIG_INPUT` / `BOTH_SCORE_PARITY` / `DIFFERENTIAL_CANONICAL` key, with a parity fixture pack authored so a build ignoring the binding scores its two trials *identically*, so neither substrate can drop it and stay green. **This is a new authorable key on both `extra="forbid"` runner-side models, so an engine of this release requires a runner image built from it for any pack declaring `bind`** — `RegisterTrial` rejects an older image — while core's `extra="ignore"` means an older engine ignores it. It is otherwise purely additive: `bind` and both operators default to `None`, and no pack that grades today changes verdict. (#681)

The universal reading is invariant under every permutation of the binder's events, which is what makes the *reported* binding reproducible too — the failure names the **set** of values that failed (`; failed under (rec='Y')`, appended to the kind's own sentence) and a set has nothing to choose. **Candidates are distinct values, not events**, two being the same only when every name's value is equal *and* of the same type, so `True` and `1` are two candidates and ten calls naming one record are one reading of the `require` tree and one reported value rather than ten. **The binder site is the direction of the implication** — binding at the write says "every record written was read first", binding at the read says "every record read was later written" — `negate` inside a bound constraint reads `∀v ¬P(v)`, "no candidate satisfies", because quantification is outermost, and `within` restricts the binder like every other matcher in the constraint. **The candidate set is itself three-valued, and reading only its two ends over-fails.** The binder resolves through the same machinery every predicate does, so it has undecidable events of its own, and a `field: result` extraction on a call the trial recorded no outcome for is a candidate whose *value* the trial does not carry — where an `args` path the call simply did not pass binds nothing at all, absent value against absent evidence, the same distinction a predicate over the field draws. The readings compared are the **empty** one, `D ∪ {u}` for **each** undecidable `u`, and `D ∪ U`; the singletons are not redundant beside the two ends, because with `D` empty the empty reading is `on_unbound` rather than a vacuous pass, so at `D = {}`, `U = {u₀ holds, u₁ fails}`, `on_unbound: fail` both ends read *fail* where the completion `{u₀}` holds. The argmax deliberately runs over every route including gated ones, so a route cannot escape its own gate by scoring at or below a clean sibling; the escape that remains one level up — trip a route's gate *and* sandbag that route so a clean one strictly outscores it — is real, ships documented, and is pinned by a characterisation test rather than claimed closed. **Wire**: `TraceConstraintResult` gains `string severity = 7`, and `Grade` gains `TraceChecksSummary trace_checks_summary = 11` — `winning_path`, `gate_failed`, `failed_gate_ids`, and one `TracePathResult` per declared route carrying that route's own score, never zeroed, so the max the component took is auditable from `grade.yaml` alone. A message rather than four scalars, because proto3 scalars have no presence and a `gate_failed` of `false` decoded from a runner predating the field is a gate silently opening; a summary the host cannot read **fails the grade parse** rather than being dropped. Both fields are written on every graded trial, matching their unconditionally-serialised sibling `trace_check_results`. **These are new keys on `extra="forbid"` runner-side models, so an engine of this release requires a runner image built from it for any pack declaring either** — `RegisterTrial` rejects an older image — while core's `extra="ignore"` means an older engine ignores them. `cache_debug` is the only shipped pack that declares them (see the entry below; scores on that pack are not comparable across the change) and no other pack changes verdict. Two adjacent limits are declared rather than closed: a `GradingKey` carries one `runner_field`, so a constraint kind written only inside a route falls outside the per-kind ledger's "populated ⇒ accounted" guarantee, which the manifest entry now says (**#772**); and `lot_ops_01` still passes an agent that double-posts the corrective action, a one-line application of this feature (**#773**) (#680)

- **grading**: **`grading.yaml` gains a `trace_checks` block — a declarative vocabulary for what the agent did and in what order.** A constraint carries an `id`, a `description`, an optional `weight` and `on_missing`, an optional inclusive `within` turn window, and exactly one of **ten** constraint kinds under `require`: `present`, `absent`, `count`, `before`, `immediately_before`, `absent_before`, `absent_between`, `all_of`, `any_of`, `negate`. Matchers select timeline events by a required `kind` (`tool_call`, `tool_result`, `assistant_message`, `user_message`) and carry `ValuePredicate`s over the fields that kind actually has — `tool`, `executor`, `args` (nested, dotted paths), `status`, `result`, `text` — where a predicate is the **conjunction** of the fifteen operators it declares (`equals`, `equals_ci`, `contains`, `contains_ci`, `not_equals`, `regex`, `gt`, `gte`, `lt`, `lte`, `in_`, `not_in`, `len_gt`, `len_gte`, `exists`), deliberately unlike `state_checks.jsonpaths`, which rejects a second operator. This expresses what `transcript_rules` structurally cannot: ordering, scoped negation, non-equality argument predicates, nested argument paths, counting, and a call's status or outcome. **The block is authorable and validated here; the entry above is where both substrates score it.** `latency_seconds` is **not** matchable: wall time is not compared across substrates, so grading must not depend on it. A `result` predicate is admitted only beside a `status` predicate reading exactly `{equals: success}`, rejected at load naming **#717** — a successful call's result text is byte-identical across substrates and canonically pinned, a failed call's is not, so matching failure text would grade differently on the two substrates; assert `status` instead. **`tolokaforge validate` constructs the whole block**, so every shape that could only ever select nothing is heard before a trial is paid for: an unknown operator, kind or matcher field (`extra="forbid"` throughout); zero or two kinds under one `require`; a predicate declaring no operator; a predicate on a field the kind never carries; `immediately_before` without an explicit `among` (there is no default — events interleave inside a turn, so `tool_calls` cannot express confirm-before-acting and `events` cannot express two consecutive calls); `any`/`all` on a window anchor, whose domain is restricted to `{first, last}` because over an interval the other two collapse onto them; `on_missing` on `present`, `absent` or `count`, whose verdict is itself the match; `count` with no bound or with `min > max`; a duplicate constraint `id`; a `within` window that is inverted or restricts nothing; a `weight` that is not a positive finite number, because a zero weight is a declared check contributing to neither side of the fold and "evaluated but not scored" is `severity: gate`; and a block that is not a mapping at all (a constraint indented directly under `trace_checks:` makes it a list), rejected naming the file, the key and the shape received. **This is a new authorable key on both `extra="forbid"` runner-side models, so an engine of this release requires a runner image built from it for any pack declaring the block**; core's `extra="ignore"` means an old engine ignores it, and no shipped pack declares one. `TraceEventKind` moves to the leaf `tolokaforge/core/grading/trace_event_kind.py` and is re-exported from `trace_timeline`, so the timeline and the matchers that select on it name one enum rather than two that can drift (#678)

It counts assistant **generations**, so three tool-call-only turns satisfy `min_assistant_turns: 3`; the sharper "did the agent answer" check is #678. A declared floor is also the one transcript rule evaluated on an events-less timeline, where its siblings still record `the trial's timeline carries no events` — absence is precisely the answer this key asks for, and leaving the blanket skip in place would have re-opened the vacuous pass one level up. **This is a new authorable `grading.yaml` key on the `extra="forbid"` runner-side `TranscriptRulesConfig`, and the engine emits the field on every pack carrying a `transcript_rules:` block — as `null` when the pack declares no floor — so an engine of this release requires a runner image built from it for every such pack, whether or not the pack asks for a floor** (`RegisterTrial` rejects it otherwise); old engine + new runner is safe, and core's `extra="ignore"` means an old engine ignores the key. Every existing pack is unaffected — the field defaults to unset and no pack in `examples/**` declares it. The manifest entry claims `BOTH_SCORE_PARITY` at `DIFFERENTIAL_CANONICAL`, the only `transcript_rules` key that can. **A turn window no trial can land in is rejected at load**: a `min_assistant_turns` above `max_turns` admits no assistant-turn count, so the component would be `0.0` however the agent behaved, and `tolokaforge validate` now rejects such a pack naming both keys and both values instead of letting the run be paid for first. Measured: all 37 declared `transcript_rules` blocks across `examples/**` and `tests/data/**` construct cleanly under both narrowings, so the widened gate rejects nothing that loads today (#677)

1. **`tolokaforge.cli.*` modules renamed to `tolokaforge.dx.*`.** The Click command tree, Rich panels, banners, and dry-run renderer are now the reference terminal front-end and live under a namespace whose name signals their pluggability role — the same `RunDisplayEvents` Protocol (in `tolokaforge.core.run_display_events`) admits alternate front-ends. 3. **Console log line shape changed to `HH:MM:SS.mmm | LEVEL | k=v | message`.** The legacy `"%(asctime)s - %(name)s - %(levelname)s - %(message)s"` format (seconds resolution, inline `(k=v, k=v)` in the message string) is gone. (#279)
4. **`tolokaforge run` with zero tasks now exits with code `1`** (previously exited `0` with a red "No tasks found!" line on stderr). Callers relying on the silent-success behaviour should either pre-filter empty task sets or handle the non-zero exit. (#280)

## v0.2.1 (2026-05-29) — LLM Reasoning & Observability Overhaul

### Breaking Changes

1. **`ModelConfig.reasoning`** migrated from bare string to `ReasoningConfig` struct. YAML configs using `reasoning: "medium"` now raise `ValidationError` at load time — migrate to `reasoning: {mode: adaptive, effort_hint: medium}` or equivalent. See [`docs/CONFIG.md`](docs/CONFIG.md) § `reasoning:`.
2. **`GenerationResult.token_usage: dict`** removed — replaced by `GenerationResult.usage: Usage` (full Anthropic + OpenAI accounting incl. cache + reasoning tokens).
3. **`Metrics.tokens_input`** / **`Metrics.tokens_output`** removed — replaced by `Metrics.usage: Usage`. Aggregators expose `avg_<field>` / `total_<field>` per `Usage` field (e.g. `avg_reasoning_tokens`, `total_cache_read_input_tokens`).
4. **`Message.reasoning: str`** migrated to `Message.reasoning: StructuredReasoning | None` — preserves provider signatures + block types for replay.
5. **`tolokaforge.core.model_client`** / **`tolokaforge.core.model_policies`** modules deleted — every concept moved into `tolokaforge.core.llm.*`. Update imports accordingly.
6. **`in-process` runtime mode removed.** Docker is now the only supported runtime (`runtime: "docker"`). All tool execution is routed through the containerised executor service. Existing configs that specify `runtime: "in-process"` must be updated to `runtime: "docker"`.

### Fixed

1. **P1 / GPT-5.5 Decimal tool-call 500s** — `StrictSchema` now strips RE2-incompatible `pattern` + `format` keys and collapses Pydantic's `Decimal` `anyOf{number, string+pattern}` idiom to `{type: number}`. Four OTS domains that scored 0.000 on gpt55 now return valid tool calls.
2. **P2 / Qwen dict-map stringification** — new `qwen` preset wires `schema_sanitizer: strict` + `response_policy: array_dict_map` + `prompt_policy: dict_map_hints`. `qwen/*` and `qwen3*` now handle `Dict[str, T]` parameters correctly.
3. **P3 / Claude 4.7 ignores `reasoning: medium`** — new `anthropic_claude_4_7` preset emits canonical litellm `thinking={"type":"enabled","budget_tokens":N}` kwarg + drops `temperature` / `top_p` / `top_k` when thinking is active.
4. **P4 / Anthropic thinking blocks dropped across turns** — new `ReasoningCodec` abstraction captures full `{type, thinking, signature}` blocks on extraction and splices them back via `thinking_blocks` on assistant message dicts for interleaved-thinking replay.
5. **P5 / user-simulator prompt never persisted** — new `Trajectory.user_system_prompt` field captures the full simulator system prompt on first turn.
6. **P6 / effective tool schemas never persisted** — new `results/tools_schemas/<task_id>__<model_id>.json` sidecar dedup'd per `(task, model)` via filename.
7. **P7 / cache + reasoning token counters lost** — new `Usage` dataclass + `UsageExtractor` reads every normalised litellm field: `prompt_tokens`, `completion_tokens`, `reasoning_tokens`, `cached_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, plus `provider_raw` for forensics. OpenRouter-routed Anthropic caching now surfaces correctly — reads `prompt_tokens_details.cache_write_tokens` / `cache_read_tokens` as a fallback when top-level Anthropic fields are zero.
8. **P8 / no `cache_control` markers on Anthropic calls** — new `AnthropicEphemeralCache` automatically marks the last system-prompt content block + last tools entry with `cache_control: {type: ephemeral}` (5-minute TTL, Anthropic default).
9. **P9 / `reasoning: medium` abstraction leak** — new `ReasoningConfig(mode, budget_tokens, effort_hint, display)` provides explicit per-provider routing. Single in-repo legacy config migrated; external configs rebase in lockstep.
10. **P10 / no shared per-provider integration scaffolding** — new `tests/integration/llm/` with `Capability` enum + `ModelCertificate` registry; per-capability tests auto-skip with explanatory messages based on each model's declared certificate. See [`docs/ADD_NEW_MODEL.md`](docs/ADD_NEW_MODEL.md).
