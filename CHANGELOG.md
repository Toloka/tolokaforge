# Changelog

All notable changes to this project are documented in this file.

## Unreleased

### Changed

- **grading**: **`state_checks.db_probes` is exclusive with the other state sources, and a pack declaring both stops loading.** A probe declared beside a non-empty `state_checks.jsonpaths`, or beside a `state_checks.hash` block that is enabled and names an `expected_state_hash` or `golden_actions`, hands one `state_checks` component two candidate verdicts with no share to fold them by — and the two substrates did not discard the same one. **Runner-side the probe filled the slot and the other source's verdict was erased**, measured through `combine_grade_components` on the parent commit with `combine.weights.state_checks: 1.0`: a matching hash *and* every JSONPath assertion satisfied, beside a failing probe, folded to **`0.0` / fail**, while a failing hash with every assertion violated, beside a passing probe, folded to **`1.0` / pass**. The component was the probe's answer, and nothing the author's other source produced could move it in either direction — so the refusal is unconditional on magnitude rather than a rule about which score is larger. **Core-side the opposite**: it has no probe evaluator at all (`state_checks.db_probes` is `RUNNER_ONLY` — the DSN resolves only inside the task's docker network, which the runner container joins and the host-side engine does not), so it folded the hash with the assertions and ignored the probe entirely, measured on the `tests/data/grading_parity/all_keys` shape as `state_checks = 0.0` **byte-identical with the probes declared and with them dropped**. One trial, two `state_checks` components, and the runtime grading-keys ledger could see neither: both keys were genuinely `EVALUATED` at their invocation sites, and the discard happens downstream of the accounting (#675). **Both `StateChecksConfig` models now refuse the block**, from one message naming both sources and the two fixes — *keep `db_probes` and drop the other source*, or *drop `db_probes` and let the hash and `jsonpaths` grade the state*. Which surface an author hears it from depends on whether the block writes a `hash` mapping, because `tolokaforge validate` constructs the core config on any declared `hash` block before it runs the authoring gate: probes beside `jsonpaths` alone reach the gate, so the finding is batched at `state_checks.db_probes` beside every other finding in the pack, while probes beside a `hash` mapping are refused by that construction first and the same sentence arrives as a **config load error**, the only defect reported. The run's pre-flight (and `tolokaforge prepare` through it) rejects the pack on the same predicate; the runner rejects it at **`RegisterTrial`**, which is what protects a new runner image against an older engine that never checked; and `resolve_state_checks_component` raises at the fold, so a config that reached grading without passing a gate fails loud instead of discarding a verdict. Probes beside a *disabled* hash block still load — that hash produces no verdict, so nothing is discarded. **What the fix costs is not the same on both substrates, and only one of the two loses grading that worked.** A pack graded runner-side was already decided by the probe alone, so its historical scores were the probe's and dropping the other source changes no number it ever published. A pack graded core-side — the `NativeAdapter` helpers, any re-grade of a recorded bundle — *was* getting the author's hash/JSONPath verdict, and refusing the block takes that away: that is the one shape where this migration costs real grading, and the fix that keeps it is to drop the probes rather than the other source. **In-repo movement is one test fixture**: `tests/data/grading_parity/all_keys` dropped its `db_probes` block (`tests/data/**` is not a published surface; the pack existed to declare every manifest key in one place, a claim that is now a union over it and the probe-only `tests/data/tasks/db_probe_grading`). **No shipped `examples/**` pack is affected** — the two declaring probes, `multi_service_lot_ops`'s `lot_ops_01` and `multi_service_helpdesk_workflow`'s `helpdesk_01`, declare `db_probes` and nothing else under `state_checks`. Re-measured over all **93** authored packs, **24** declare a state source the fold also scores and **69** declare none, which is why the corpus control splits on what each pack declares: injecting a probe into one of the 24 must be refused, and injecting one into the 69 must not, because there the injection leaves a probe-only block. **Open edges, deliberately left open:** whether three state sources may ever compose is **#848**'s question, and this answers only "not until someone argues the weight" — a refusal is relaxable later without breaking an author, where a silent default in the field would not be; a translated `expected_hash` no runner path reads stays **#693**'s. And one shape still reaches the fold rather than a gate: `hash.enabled` truthy with **no** declared source, beside non-empty probes, satisfies neither validator's condition — both require a *declared* source, and a sourceless enabled hash is refused at the flag by its own rule — yet the runner grades that hash against the trial's initial state anyway and so produces a real verdict, so the config raises at **grade** time. It is reachable from a directly-built runner config and from a bundle recorded before #814's gate rule existed, and zero in-repo. **Out of tree is unmeasurable from here** (gotcha #10): a pack under `tasks/` declaring a probe beside a hash source or a JSONPath assertion stops loading on both substrates, and its author sees a hard error naming the two fixes (#731, #686)

- **grading**: **a state hash the pack asked for is checked, or the pack does not grade — and a golden replay with no world to be built in is refused by the authoring gate before a trial pays for it.** Core returned *no hash verdict* plus a reason string when a hash-enabled block's effective source was `state_checks.hash.golden_actions` and the engine held no task directory, `initial_state` or `mcp_server` to replay them against. #733 made that absence visible for a pack declaring **no** JSONPath assertions beside the hash — the component is unevaluated rather than a vacuous `1.0` — and left behind the shape that declares them: there the component was the assertion score alone, the hash contributing nothing, while `grade.reasons` said so in a sentence no consumer reads. Re-measured on `tests/data/tasks/shop_orders_02` (seven assertions, `hash.weight: 0.60`, `combine.weights.state_checks: 0.70`) with `tools.agent.mcp_server` withheld from `task.yaml` and nothing else changed, on a final state satisfying all seven assertions while diverging on a row none of them address: `state_checks` was **`1.0`** where an engine holding the prerequisite reports **`0.4`**, and the trial **`0.7000`** where it reports **`0.2800`** — **+0.6 on the component and +0.42 on the trial**, with the prerequisite withheld against supplied rather than after against before — leaving the wrong trial indistinguishable from a perfect one, which scores exactly `1.0` / `0.7000` on the same engine. `grade_trajectory` now raises **`UnbuildableGoldenReplayWorld`**, a subclass of `GoldenReplayError` importable from **`tolokaforge.core.grading.golden_replay`**, naming every absent prerequisite in one message by the `task.yaml` key an author writes — `initial_state.json_db`, `tools.agent.mcp_server`, with the task directory named as the caller's omission since no author supplies it — and the trial is left unscored, the answer a replay that cannot execute has always produced. **This finishes a decision already recorded rather than opening one:** the #686-era ruling below states that a pack declaring `golden_actions` with no `initial_state.json_db` raises rather than scoring `0.0`; the case one level up — `initial_state` absent entirely, or no `mcp_server` — returned no verdict instead, so one authoring defect took two paths depending on whether `initial_state:` existed at all. Both are now the same raise, and an `initial_state.json_db` written as an **inline mapping** takes it too, where it previously escaped as `Error executing golden actions: unsupported operand type(s) for /: 'PosixPath' and 'dict'` — loud and attributable to nobody. **The published Python API is the compatibility surface, and its core-substrate construction sites are exactly these:** production is one, `BaseAdapter.grade` (`adapters/base.py:520`), which supplies `task_dir` always, `task_initial_state` always — `TaskConfig.initial_state` carries a `default_factory`, so that term was never falsy there and the old three-term guard read as if it checked three things while only the third could fail it — and `task_mcp_server` only when the task declares `tools.agent.mcp_server`; the rest is 30 direct constructions across 9 test files (29 before this change) plus the one example in `docs/REFERENCE.md`, whose signature was two parameters short — the two this change is about — and is corrected here with the raise semantics beside it. Two of those test constructions moved, both of them #733's observability locks asserting the deleted reason string: `test_a_pack_with_no_evaluable_source_is_unscored_and_still_says_why` and `test_golden_actions_without_replay_context_name_the_skipped_check`. **An external caller** of `GradingEngine` or `BaseAdapter.grade` on such a pack now has an exception to catch where it previously received a grade whose `state_checks` was the assertion score; its fix is to pass the pack's `task_initial_state` / `task_mcp_server`, or to stop declaring `golden_actions`. **The `expected_state_hash` precedence bounds every rule here.** `_check_state_hash` compares a truthy `expected_state_hash` in process and returns before `golden_actions` is read, so a pack declaring **both** sources never replays, needs no world, and is refused by neither the engine nor the gate — measured on `tests/data/grading_parity/all_keys`, which declares both beside an inline-mapping `json_db` and no `mcp_server`: it reaches the literal comparison and draws no golden-actions finding at all. The flag and both sources are read for **truth** rather than for `true`, as the two rules beside them already are. **The gate refuses the shape pre-run**, so `tolokaforge validate` and the orchestrator's pre-run preflight (and `tolokaforge prepare` through it) **reject a pack they previously accepted**: one ERROR per withheld fact at `state_checks.hash.golden_actions`, naming the key to write in `task.yaml`. That withheld `shop_orders_02` copy reported `errors=() advisories=() unchecked=()` — a clean bill of health for a pack whose primary state source cannot run — and now fails `validate` non-zero with *"this task declares no tools.agent.mcp_server, whose tools the golden actions call"*. `inspect_grading_authoring` gains a third resolvable input beside the tool inventory and the effective combine, because the two facts it reads are task-level and were unreadable from `grading.yaml`; a caller that cannot resolve them skips the rule where it would have run rather than failing a pack. **Movements on shipped packs: none**, re-measured over all **93** authored packs: of the four declaring a truthy `hash.enabled` with truthy `golden_actions`, three declare both prerequisites (`shop_orders_02` and `food_delivery_2`'s `order_modify_with_checks` and `order_six_items_golden`) and the fourth is `all_keys`, excluded by the precedence above; `validate --tasks "examples/**/task.yaml"` stays at 29 valid / 2 invalid. **The runner is unchanged, and the two substrates now agree by refusing rather than by both grading.** Its replay world *is* the live trial — the tools `RegisterTrial` registered, over db-service's state — so it has nothing to lack and can still produce a verdict for a shape core cannot compute at all; with the gate refusing the shape, that divergence survives only in a config no gate saw, such as a bundle recorded before the rule, which is what `state_checks.hash`'s manifest reason now records. **Open edges, deliberately untouched:** whether a verdict over a partial world should exist when an action ran and raised (#816); an action reporting failure by returning `{"error": …}`, invisible on both substrates (#831); `golden_actions` under a falsy `hash.enabled`, and what a non-list `golden_actions` *is* — both new rules read its truthiness and never its shape, so `golden_actions: "write_file"` with no world is refused for the world while the name rule reports nothing (#832); unifying the three golden-action name namespaces (#815); hash-verdict binariness (#742); typing the untyped `state_checks.hash` block, which every new reader still reads defensively (#730); a translated `expected_hash` no runner path reads (#693); `db_probes` overwriting the component (#731); and `BaseAdapter.compute_golden_hash`, a documented contract method with no caller (#836). **Out of tree is unmeasurable from here** (gotcha #10): a pack under `tasks/` whose effective hash source is `golden_actions` with no `mcp_server` reference starts failing `validate`, and raises if it reaches a grade at all — which is the point of the change (#729, #686, #733)

- **grading**: **a golden replay either builds the world the pack describes or produces no verdict, and one that skipped an action says so on both substrates.** Every authored `state_checks.hash.golden_actions[].name` resolves before the first action runs, so a partially replayed golden world is never built and no trial is hashed against one. **Core** skipped a name outside the pack's `TOOLS` map — and an action declaring no name at all, the key absent or written `""` or `null` — with a `logger.warning`, returned the partial world as the oracle, and graded the trial against it. Measured on `tests/data/tasks/shop_orders_02`, whose golden path places an order and confirms payment: with `confirm_payment` misspelled `confirm_paymnet`, a trial that placed the order and never paid — the exact failure the pack exists to catch — scored `1.0` "State hash matches", while a *correct* trial scored `0.0` against a bare diff naming the order's `status` and the customer's `balance` and never the typo; an action carrying no `name` key produced the same wrong `1.0`. Both shapes now raise `UnresolvableGoldenAction`, naming every offending action with its index and the four names that pack resolves against in one error rather than the first one found, and nothing in `tolokaforge/` catches it — **the trial is left unscored**, the answer a replay that cannot execute has always produced. **The runner** answered the same shape with `GradeTrial success=true` carrying a real `state_checks` component computed against a world the action never touched, and `GOLDEN REPLAY ERRORS: Golden action <i> (<name>): tool not found` appended to `reasons` — measured on the hash-composition probe pack driven off its initial state first, `state_checks` `0.0` — and now answers **`success=false`**, its `error` naming the action and the tools `RegisterTrial` registered for the trial. Resolution is the first thing hash grading does, ahead of the MCP state sync, the `pre_golden` snapshot and the reset, so a pack defect writes nothing to the trial's database at all rather than snapshotting and restoring around a failure it could have raised first; the trial still holds what the agent left behind and the host can re-grade it. **An action that resolved, ran and *raised* is the other case, and its verdict stands**: the replay continues past it, because tau-bench continues past a precondition failure and golden-action hash grading is the tau-style path, so the partial world is hashed and yields a binary verdict as it always did. What is new is that both substrates name what did not run, in **one sentence written once** — `GOLDEN REPLAY ERRORS: N of M golden actions did not run, so the state the trial was hashed against is a partial golden world: [i] <name> raised <Type>: <message>`. The `GOLDEN REPLAY ERRORS:` **prefix is deliberately unchanged**: #599 names a downstream consumer (`toloka-partners/tolokaforge-tools`, `benchmark-analyzer find_incomplete`) that buckets trials by matching it. The body did change — the runner's per-action `Golden action {i} ({tool}) failed: {Type}: {msg}` entries joined by `"; "` became the count sentence above, and **core emitted nothing at all** and now emits the same sentence into `grade.reasons`. **That annotated verdict can still be the wrong one.** Reproduced and asserted as current behaviour: on `shop_orders_02` with `confirm_payment`'s kwargs written `{"order_idd": "O-001"}` — the one defect shape that genuinely raises, since a tool's *declared* failure is returned rather than raised — the replay stops where the failing agent stopped, so a trial that placed the order and never paid still scores `1.0` "State hash matches", now beside a sentence saying 1 of 2 actions did not run. The reason is new; the wrong score is not fixed, and whether a verdict over a partial world should be admissible at all is **#816** — the sentence annotates such a verdict, it does not settle it. **The returned-error-payload path stays invisible (#831).** An action that ran, reported failure by returning `{"error": …}` — what every tool built through `create_server` does with its own declared failures, since `DomainToolRegistry.tool` converts a `ToolError` into a return payload — and changed nothing returns normally, so neither substrate can tell it from a success: measured on the same pack, `confirm_payment(order_id="O-999")` returns `{'error': "Order 'O-999' not found"}`, records no failure, emits no sentence, and the wrong trial scores `1.0`. So of the issue's two silent paths one is closed outright and the other only for actions that *raise*. **The authoring gate refuses both unresolvable shapes before a run pays for them**, so `tolokaforge validate` and the orchestrator's pre-run preflight now **reject a pack they previously accepted**: one ERROR per offending action at `state_checks.hash.golden_actions[i].name`, under a truthy `hash.enabled` only, resolving against the tools the task declares — `tools.agent.enabled ∪ tools.user.enabled`. That namespace is **stricter than either replay substrate** (core matches the pack's `TOOLS` map, the runner the tools it registered, and neither is readable before a run without importing the pack's server module), so a native pack whose golden action names a `TOOLS` entry it gives no actor replays fine and is refused here; no pack in this repository has that shape, and **#815** owns unifying the three namespaces — the two replay ones still differ, and the runner still accepts a single registered `…_<name>` suffix where core does not. A `golden_actions` list under a falsy `hash.enabled` is refused by neither this rule nor the flag-versus-source rule beside it, which is **#832**. **Verdict movements on shipped packs: none**, re-measured: no `golden_actions` declaration under `examples/**` at all (the two greppable hits are a comment and a prose mention), and all three in-repo packs with a reachable replay — `tests/data/tasks/shop_orders_02` and `food_delivery_2`'s `order_modify_with_checks` and `order_six_items_golden` — resolve every authored name against their MCP module's `TOOLS` map. The only movement is one fixture the gate refuses, corrected here: `tests/data/grading_parity/all_keys` declared a golden action named `close_widget` while giving its actors only `write_file`, and now names `write_file`. **Out of tree is unmeasurable from here** (gotcha #10): a pack under `tasks/` carrying a misspelled golden action starts failing loudly — core unscored, the runner `success=false`, `validate` non-zero — which is the point of the change and will read as a regression to whoever runs it first (#734, #599, #815, #816, #831, #832)

- **runner**: **a run refuses to start against a pack whose grading cannot be graded, naming every offending task.** Before it schedules the first trial — and at `tolokaforge prepare`, so a distributed enqueue is rejected once rather than by every worker identically — the orchestrator makes one pass over every selected task and puts its grading block through the same predicate `tolokaforge validate` applies. That covers the authoring rules checked against the task's tools *and* every migration rejection the typed grading blocks carry: a removed `state_checks.env_assertions` / `db_hash_check` key, and the free-text `rubric` / `output_schema` / per-task `model_ref` shapes, were previously only rejected while artifacts were written — the last phase of a trial the author had already paid for (#696). The abort lists **every** offending task rather than the first, because an author fixing a run's packs wants the list. The pass resolves each task's wire description once and keeps it, so the trials that follow reuse it; a task naming an adapter the host has not installed is rejected in the same pass. `evaluation.grading_validation.fail_on` (a new optional block, default `advisory`) names the least severe finding class that is fatal — `advisory` fails on errors and advisories, `error` on errors alone — and what the gate could not check is logged and fails nothing under either. An existing run config is unaffected — but a run whose pack was already mis-authored now aborts at startup instead of grading with a check that silently decided nothing. Note that `evaluation` is `extra="ignore"`, so a misspelled *block* name (`grading_validaton:`) is dropped without a word and the defaults stand; the block's own fields are `extra="forbid"` (#679, #696)

- **grading**: **a grading block that names a tool the task does not have is now an authoring error, heard before a trial is paid for.** Three shapes were reproduced end to end and all three charge the author's typo to the agent or to nobody: `tool: { equals: http_reqest }` in a `present` matcher scores the component `0.0` with `present is unmatched: match selected no event`, byte-identical to a genuine agent failure; the same typo under `absent` scores `1.0` against a timeline where the tool *was* called, so the check can never fail; and an uncompilable `regex` raises `re.error` out of the evaluator at grade time, which core lets propagate and the runner folds into a failed grade response — losing the trial, not the constraint. `tolokaforge validate` and (from the pre-run gate) a run now check the block against the tools the task gives its actors: **errors** for a tool name outside the declared set (in `trace_checks` matchers and in `transcript_rules.tool_expectations`), for an argument name outside the properties of a tool whose schema forbids extras, for a pattern that does not compile, and for `state_checks.hash.expected_state_hash` declared under a falsy `hash.enabled` — a confirmed silent no-op, since both substrates read the flag before the hash; the flag is read for truth rather than for `true`, because core branches on its truthiness and the runner coerces it, so `enabled: 1` grades and loads; an **advisory** for an argument name outside the properties of a tool whose schema *permits* extras, which an MCP schema always does, so hard-failing would enforce a claim the schema does not make. What the schema cannot answer is reported as **unchecked and never fails anything** — a separate channel, not a third severity, so the gate has no false-reject mode: nothing reads it to decide whether to raise, and the CLI prints it beside the task because a gate that could check nothing must not read as a clean bill of health. An `args` path is checked at its **first segment only** (`json.q` on `http_request` is checked at `json` and stops, because `json`'s schema declares no properties); descending further is **#765**. A tool named by `regex` rather than by `equals` / `in_` produces no finding — a pattern names a set, not a token. Measured on the shipped corpus: all **57** packs under `examples/**` and `tests/data/tasks/**` that ship a `grading.yaml` produce **zero errors and zero advisories**, so nothing that grades today stops loading (#679)

- **grading**: **an ordering constraint written over one matcher is rejected at load unless some trajectory can decide it.** Both sides of a `before` carrying the same matcher, or an `absent_before` / `absent_between` forbidding the very events its window is measured from, is usually a constant — nothing follows the last of a matched set and nothing precedes the first — so the check passes or fails every trial whatever the agent did, which is the same defect as an unsatisfiable count bound. Measured cell by cell against the evaluator at zero to four matching calls: of the 38 quantifier combinations these shapes admit, **ten** still say something and are kept — `before` and `immediately_before` with `left ∈ {first, any}` and `right ∈ {last, any}` ("the events occur at least twice", except `immediately_before` `first` before `last`, which reads exactly twice), `absent_before` anchored `last` ("the events occur once"), and `absent_between` from `first` to `last` ("exactly twice"). Of the other 28, twenty-seven are false at every trajectory; the twenty-eighth — `absent_before` forbidding its own anchor, anchored `first` — is **not** a constant but decides exactly what `present` decides, so it is rejected as `present` written the long way round rather than as a check no agent can move. All 28 are load errors naming the shape that would express the intent. No shipped pack writes one (#679)

- **cli**: **`tolokaforge validate` exits non-zero, and validates the task a run would load.** The command counted failures, printed `N valid, M invalid` and returned `0` regardless — so the four CI steps that run it (`ci.yml:126, 198, 302` and `release-gate.yml:55`) could never fail a build, and every "fails `validate`" contract in the docs was unenforceable. It now exits `1` when any matched task fails to load, after printing the same per-task lines and summary, and **`1` when the glob matches no file at all**, naming the pattern: a pattern selecting nothing validates nothing, which is exactly the shape a CI glob drifts into (#764). **A script or CI step that treated a failing `validate` as success now fails.** Measured on the shipped corpus: `examples/**/task.yaml` → 28 valid / 2 invalid, exit `1` (the two are the `terminal_bench` pair, which declare no `task_id` / `description`); both CI globs — `examples/native/*/dataset/**/task.yaml` (23/0) and `tests/data/tasks/wire_probes/dataset/**/task.yaml` (20/0) — stay clean and exit `0`, so no lane reddens. Each task now also loads **under its enclosing project**: `validate` resolves the `project.yaml` above the task and layers its `task_defaults` beneath the task's own fields, the same layering the orchestrator applies, so the object validated is the one the run loads rather than a project-less reading of it — measured, that changes the effective config of 18 of the 28 example tasks and breaks none. `project.default_environment` is deliberately *not* layered: it binds into a `TaskDescription`'s `EnvironmentManifest` and `validate` builds none. A `project.yaml` that fails to load fails the tasks beneath it, naming the project file, and the rest of the glob is still validated. **`make validate` gains a directory guard** — task packs are cloned separately, so with `TASKS_DIR` (default `tasks`) absent *and* `TASKS_GLOB` still the default derived from it, the target prints a skip reason and exits `0` instead of failing on an empty glob. Naming a `TASKS_GLOB` runs it whatever `TASKS_DIR` holds, so pointing the target at a pack elsewhere is never silently skipped. The dev MCP's `validate_tasks` answers for the same default and skips the same case (#679)

### Fix

- **grading**: **a source that evaluated nothing contributes nothing, a fold that counted nothing says so, and core-side scores on two shipped example packs are not comparable across this change.** One rule now holds on both substrates and in every consumer that re-folds a recorded config: a component is *scored* only when a source the substrate evaluated produced a verdict. A source declaring nothing to evaluate — an empty `state_checks.jsonpaths` list, or a `state_checks` block carrying only `id_fields` — produced a vacuous `1.0` core-side, so a trial that did nothing at all could score a perfect `1.0` with `reasons` reading *"All checks passed"*, and on a pack whose hash prerequisites were missing the score contradicted the reason printed beside it (#729's observability half; the raise-or-not question it left open is answered by the entry above). Such a source is now left **unevaluated**, and the fold decides on the components that were actually decided. **Three shapes stop loading**, each an authoring error at `tolokaforge validate` and at the run's pre-flight gate, read against the **effective** `combine` after project inheritance so a task inheriting its weights is not refused for declaring none: a component section that asserts nothing, a component the pack configures that the effective `combine.weights` never weights, and a `combine.weights` key naming a component the pack never configures. The first covers the empty mapping (`state_checks: {}`, `transcript_rules: {}`, `custom_checks: {}` — generalising the `trace_checks: {}` and `llm_judge: {}` rejections that already shipped) **and** the non-empty block whose every key configures how the component runs rather than what it checks: a `state_checks` declaring no source (`jsonpaths: []`, or only `id_fields`), a `transcript_rules` whose every rule list is empty (`required_actions: []`, `must_contain: []`, a `tool_expectations` expecting neither), and a `custom_checks` naming a checks file under no `enabled` flag, which the component's own default leaves unrun. Each of those scored — or, for the unflagged suite, folded as — a vacuous pass while reading as configured, so the gate refuses them at the key whose fix they take, naming what to declare or telling the author to drop the block. `enabled: false` is a decision, not an omission, and still loads. What the gate cannot reach — a `GradingConfig` built in process, and a bundle recorded before these rules that `retrace` and `reconcile` replay — both folds now guard themselves: a component a substrate scored whose share `combine.weights` does not declare raises `MissingComponentWeight` naming the component and both one-line fixes, on both substrates, because `1.0` invents a share the author never gave it and `0.0` discards a verdict the substrate produced. **A fold with no weighted scored component decides rather than aggregating**: nothing configured and nothing weighted is `(1.0, True)` — the deliberately non-scoring pack, which asked for nothing and is owed nothing — and anything else is `(0.0, False)` with a reason naming what the config asked for, whether that is the components that produced no verdict, the scored components whose shares sum to zero, or the weight keys naming nothing the pack configured. A fail here never names nothing, because a `0.0` beside components that all read as passing is the defect this rule exists to remove.

- **grading**: **the core grading engine honours `combine.method` instead of always computing a weighted mean.** Both substrates now fold through one shared `combine_by_method`, so `all` reports the weakest component and `any` the strongest wherever the trial is graded, not runner-side only. Core did not read the key at all — `combine.method` appeared nowhere in `core/grading/combine.py`, whose fold was an unconditional weighted mean, so `method` could not have mattered — which is why a pack declaring `all` scored one number under `validate` and another in production. **A pack declaring `all` or `any` therefore scores differently core-side**: under `tolokaforge validate`, in the `NativeAdapter` helpers, and on any re-grade of a recorded bundle. It converges on the runner's answer, the number production has always published. No `examples/**` pack declares either, so nothing in this repo moves; per gotcha #10 `tasks/` lives outside it, so the out-of-tree corpus cannot be declared unaffected. **The two substrates still build different component maps, and for these two methods that is a verdict flip rather than a magnitude gap**: core admits only the components `combine.weights` names, while the runner admits every component it evaluated at an invented weight of `1.0`, and `all` / `any` aggregate that map alone. Measured on `state_checks: 0.0` and `transcript_rules: 1.0` at `pass_threshold: 0.8` with only `state_checks` weighted — `any` gives `(0.0, False)` core-side against `(1.0, True)` runner-side. Declaring a weight for every component the pack scores closes that divergence — on the same trial with both weighted, all three methods answer identically on both substrates. The passing verdict is named **`no_counter_evidence`**, not `supported`: it says no trial in this corpus contradicted the claim over N observations, and it is the only verdict exit `0` means. Every entry's report carries the **2×2 contingency table** beside κ, required rather than optional, because a corpus whose mass sits in one cell is visibly a designed experiment that an accuracy of `1.0` hides. Nothing in the report ranks or compares modes and nothing can — zero disagreements satisfies `retired`'s condition *and* `narrowed`'s, so the mode is the author's recorded judgment — which is locked by **set-equality over the report model's field names** rather than by prose, an absence-of-phrase assertion over free text passing on every implementation. The declared `was` block is verified against the rubric **each contributing bundle recorded**, not against the pack: the pack holds only the post-migration state (for a `retired` criterion, nothing at all), so the bundle is the only surviving record of the pre-migration shape, and this is what closes the bypass an author opens by changing the declaration and the pack in one commit. It also catches a corpus **regenerated after the migration**, whose evidence would silently re-base onto the state the migration produced; because the fix is counter-intuitive the refusal says so in words — "the corpus records the post-migration rubric; evidence for a migration must come from bundles recorded before it". Two bundles recording different shapes for one criterion is refused naming both, mirroring replay's existing rule for two bundles claiming one task with different blocks. **`evidence.observations` and `evidence.kappa` are read rather than merely recorded**: they are what a reviewer reads instead of re-running the command, so a run measuring **more** observations than the declaration claims, or reaching the declared count at a different κ, is refused. The rule is a bound rather than an equality because pointing `--source` at part of the declared corpus is a documented diagnostic — it is how each half of the two-arm corpus is shown to be the other's falsifier — so a run measuring *fewer* observations says nothing; κ is compared at the three decimals the report prints, which is the number an author copies. The residue is stated in the docs rather than hidden: a declaration over-*counting* its own corpus is indistinguishable from a subset run. The constraint block is resolved **from the pack** the bundle's `task_id` names — `--packs`, repeatable, default `examples/` — and there is deliberately **no** `--constraints`-style flag: measured, a valid one-line edit to the shipped constraint flips all five verdicts over the frozen corpus and reds the CI lock, where a pinned fixture would make the guard decorative. A `task_id` resolving in none of the searched roots or in more than one is an error naming the id and the roots. A trial contributes no observation when its recorded rubric lacks the criterion, its `judge_status` is anything but `completed` (an errored judge reached no verdict; folding it in as not-met would manufacture agreement with a failing constraint), its `criterion_results` is absent or empty, it holds no verdict for the criterion, or a named constraint was undecided — each reported **with its reason**, so a shrinking denominator is visible. Labels come only from the original bundle and never from a replay grade, whose deterministic components and gates are absent (#775). `reconcile` is a separate command from `retrace` because `retrace`'s exit code is reserved for the readability of a corpus — a non-discriminating constraint and a disagreement with the recorded grade both exit `0` there, deliberately — and a gate on a decision cannot live there without changing that contract. - **grading**: **a task directory may declare what its rubric is migrating into trace checks, in a new optional `migration.yaml` sidecar, and the two hazards that migration carries are refused at authoring time.** The file is optional and no existing pack changes behaviour — nothing about grading reads it. It records, per rubric criterion, the constraint ids that are a `candidate` for it / have `narrowed` it / have `retired` it, the criterion's pre-migration shape, the post-migration `combine.weights` map, and the corpus of recorded judge verdicts the claim rests on, so the claim can be checked against those verdicts rather than asserted. It is a **sidecar rather than a `grading.yaml` key** because `GradingConfig` is `extra="ignore"`, so a `migration:` key there is silently dropped, and making it a real key needs a `GRADING_KEYS` manifest entry, whose every `KeyKind` describes score production — which this metadata must never do. Every rule is an **error naming what to write instead**, raised by `tolokaforge validate` and **deliberately not** by the pre-run gate: the file cannot affect a grade, so a run must not abort on authoring metadata. Two of the rules are the reason the file exists. The **veto rule**: a `narrowed` / `retired` entry on a `required: true` criterion may only name **shared** constraints carrying `severity: gate`, because a required criterion is a trial-level veto carrying zero score share — measured, retiring one leaves the judge score bit-identical at `0.7333` and only `gate_failed` changes — so a route-scoped gate (escapable inside `alternatives`) or a scored constraint is a fraction of a component where a veto was, and nothing downstream reveals the loss. The **freed-share rule**: a `narrowed` / `retired` entry on a criterion that is *not* required must declare `combine_weights`, because a scored criterion's weight sits in the judge component's denominator, so removing one the agent failed makes the judge **more generous** — measured at `+0.667` on `cache_debug`'s `explains_mechanism`, on a trial that scored it `0.0`. A `candidate` entry is charged neither rule: it replaces nothing, so the criterion keeps both its veto and its share whatever it names, which is what both shipped candidacies are. Because the veto rule reads the author's `was`, a `narrowed` entry's `was` is **cross-checked against the criterion the pack still holds**: `was.required` and `was.kind` must equal the current ones, since an unchecked `was.required: false` escapes the veto rule outright and a flipped `kind` makes the recorded evidence incomparable with what the judge scores afterwards. **`was.weight` is deliberately free** — a criterion that now asks less may legitimately weigh less, and requiring a match would refuse a correct migration while adding nothing against the escape. A `retired` entry's `was` is not cross-checked, the criterion being gone from the pack, so no load-time source holds its pre-migration shape. `residual` is a small `extra="forbid"` model `{kind: none | text, reason: str}` rather than a string, because no one scalar carries both a sentinel and free text — measured with `yaml.safe_load`, `none` / `None` / `NONE` all parse to non-empty **strings** while `null` / `~` parse to `None`, so a `narrowed` entry writing `residual: none` would pass a non-empty check and a `retired` entry meaning exactly "nothing remains" would fail one. `retired` requires `kind: none` and a non-empty reason and `narrowed` requires `kind: text`, in both directions, because which of the two a pack means is the **author's recorded judgment** and not something evidence decides. A `candidate` carries **no** residual at all, which makes `residual`'s presence and kind a total function of `mode` — absent, `text`, `none` — so a reader can tell what an entry claims from its mode alone. `docs/TASKS.md` § Task Layout and `docs/GRADING.md` § Trace Checks document the file, and `docs/REFERENCE.md` § Configuration Schemas carries its annotated block beside `run.yaml` / `task.yaml` / `grading.yaml` (#683)

- **cli**: **`tolokaforge retrace` re-checks a recorded run's `trace_checks` constraints, and spends nothing doing it.** It rebuilds each discovered bundle's trial event timeline from the bundle's own artifacts and scores a `trace_checks` block against it through the one production evaluator — no agent, no environment service, no judge, so no container starts and no token is bought. The guarantee is structural rather than promised: a clean-subprocess probe asserts that importing `tolokaforge.core.grading.trace_replay` leaves both `tolokaforge.core.llm.client` and `tolokaforge.core.grading.judge` out of `sys.modules`, which one wired-in judge import would break. It is a **new** command in the `Runs` group; no existing command's flags, output or exit codes change. A directory is a replay bundle iff it directly holds `task.yaml` + `trajectory.yaml` — not `grade.yaml`, because a trial is worth re-checking whether or not it was ever graded — and `trace_replay` (its own output) and `replays` (judge replay's) are **reserved directory names**: a bundle beneath either, at any depth under `--source`, is not discovered, so the two commands never read each other's output — at the deliberate cost, documented rather than discovered, that a task named either would hide its own trials. `--constraints <file>` **replaces** each bundle's block wholesale rather than merging (two constraint lists folded together assert something neither was written to assert, and partial satisfaction across declared routes is already a grading bug), and the supplied block goes through the same `inspect_grading_authoring` a pack meets before a run, checked against the tool set each bundle *recorded*: an **error** aborts the batch naming the file and the defect **before any trial is re-checked**, because a misspelled tool name is one defect in one file and replayed it would arrive as a corpus of trials that all failed a constraint selecting nothing. A bundle that recorded no `tools_schemas.yaml` has an *unresolvable* tool set rather than an empty one, so its schema-dependent rules land in an `unchecked` channel the console names per bundle and once in full — a gate that could not run must never read as a clean bill of health. Each bundle's disposition is declared, never silent (`replayed` / `would_replay` / `skipped_not_applicable` / `failed`), and a failure never aborts the batch, so the readable trials are still measured. **A bundle predating call-id threading cannot be re-checked at all** and says so by name: the call id is the only key joining a call to the result it produced, and those rejections are counted apart from other unreadable inputs because that is a property of the corpus's age. The output is a discrimination report — one row per **declared** constraint, keyed by `(task_id, constraint_id)` because an id is unique only within one pack's block — carrying six verdicts (`discriminating`, `always_true`, `always_false`, `undecided_in_part`, `never_decided`, `not_measured`) whose boundaries are all-decided / some-decided / none-decided with no threshold anywhere, so `always_true` means unanimous *on complete evidence* and everything short of it is named. `not_measured` is decided ahead of every other verdict, since over zero evaluated trials "every evaluated trial was decided and all passed" is vacuously true and so is its mirror. A constraint declared inside an alternative route is measured only over the trials that route won, so it still gets a row and every row carries `route` beside `trials_evaluated`, with the denominator stated once. `trials_labelled` and `agreed_with_recorded_pass` put each recomputed verdict beside the verdict the live run recorded for **that same constraint**, joined by id off `grade.yaml`'s `trace_check_results` — never against the trial-level `binary_pass`, which would count a disagreement whenever a trial failed for reasons no one constraint is responsible for; a trial where either side is undecided, or whose bundle recorded no verdict for the id, is not labelled at all, and the trial-level pass is reported per trial instead. Evidence to read, not a check that must hold. A `--replay-id` is held to a single directory name, since the read-only guarantee is scoped to `<source>/trace_replay/<id>/` and a separator or `..` in it would name a tree outside `--source`. **A non-discriminating constraint exits `0`**, deliberately, as does a disagreement with the recorded grade — both are results, and a CI job must not go red because a corpus turned out to be uninformative; an unreadable bundle, an override the gate refuses, and a `--source` holding no bundle at all exit `1`. Artifacts land under `<source>/trace_replay/<replay_id>/`, a deliberate sibling of judge replay's tree, and the read-only guarantee is stated precisely and locked by digest: **no file that existed under `--source` before the run is modified or removed**. `docs/TRACE_REPLAY.md` documents the command and the authoring loop it exists for (#682)

- **grading**: **a trace-check verdict says whether it failed or could not be decided, and `grade.yaml` carries the answer.** A constraint whose three-valued fold reached no verdict — the usual reading of a bundle re-graded without its tool-call record, where `status` and `executor` are unreadable — was indistinguishable from one the agent definitely failed: both are `passed: false` with a prose `message`, and recovering the distinction meant substring-matching that sentence. `TraceConstraintResult` gains **`undecided`**, `true` exactly where the fold reached `UNKNOWN`, on the core model, on `runner.proto` as additive **`bool undecided = 8`**, through `GradeTrial`'s response, through the client's proto→dict lowering and onto `grade.yaml`'s `trace_check_results` entries. **Scoring does not move**: an undecided constraint still forfeits its weight and still shuts a gate it carries, and `undecided: true` beside `passed: true` is a load error on both substrates rather than a pairing any reader has to interpret. A runner predating field 8 sends `false`, and since the `RegisterTrial` skew gate only refuses an engine *older* than the runner, a new host against an old runner reads such a verdict as decidably false — the same additive-field direction `GradeComponents.trace_checks` documents, and the one-directional skew gate that would catch it is tracked on **#786** (#682)

- **grading**: **`trace_checks` grades genuinely alternative routes, and a constraint can be a check that must hold rather than a share of the score.** Two new authorable keys on the `trace_checks` block. **`alternatives`** declares **two or more** named routes (`id`, `description`, its own `constraints`); each is scored over its **decision set** — the shared `constraints` plus that route's own, normalised within the set, so routes need no weights against each other — and the component is the **highest-scoring route's**, with the winner recorded. A tie goes to a route whose gate shut and otherwise to the first declared: preferring the gated route can only ever shut a component and never rescue one, and without it the trial's verdict would turn on which of two equal-scoring routes the author wrote first. This is what `any_of` structurally cannot express: `any_of: [A_step1, B_step1]` beside `any_of: [A_step2, B_step2]` passes an agent that did half of each, which is neither route. A **single** path is the flat form written the long way round and is a load error, as are a block declaring neither key, an id repeated anywhere in the block's one id space (paths and every constraint list share it, because an id is how the grade and the pre-run gate address a sub-check), a `weight` beside a gate, `on_missing: pass` beside a gate (it would open the gate on every trial whose anchor matched nothing, and a gate carries no share for the policy to save a second charge on), and a route whose decision set has no scored member while another route's does (a constant `1.0` standing in front of every scored sibling — that gate belongs in the shared `constraints`). **`severity: gate`** marks a constraint that is not scored and must hold: it enters neither the numerator nor the denominator of the weighted fraction, a tripped gate takes the component to `0.0` and **fails the trial on both substrates** independent of `pass_threshold`, and the grade names the gates that shut and the route the score came from. The core engine had no gate path at all before this — the rubric judge is runner-only — so this is the first gate it honours. **This is the judge's required-criterion gate reused exactly**, not a second semantics: excluded from the average, the failed-id list, the component zeroing, the forced `binary_pass`, and the all-gates collapse (`1.0` when every gate held, `0.0` otherwise) — which is **not** conditional on `alternatives`, since a flat block of nothing but gates reaches it too. `tests/canonical/test_gate_semantics_parity.py` drives `aggregate_rubric` and the trace fold through one shared answer table and fails naming the cell if they disagree; no shared helper is extracted, because the trace fold's weighted fraction is held to one division and no branch while the judge's must raise on a non-positive denominator (**#771**). **An undecided gate trips it.** Undecided is not a pass in the agent's favour anywhere in this vocabulary, and a gate that opened there would be *weaker* than the scored constraint it replaced. The consequence is sharpest on a bundle re-graded without its tool-call record, which cannot read `status` or `executor`, so a gate reading either fails every re-graded trial — write gates over evidence the message view carries and keep `status` / `executor` for scored constraints, where the same limit costs a weight rather than the trial. **A path gate is a *process* gate**: it constrains how *that* route must be walked and is consulted only on the route that won, so **a gate that must hold whatever route the agent took belongs in shared `constraints`**, where it is in every decision set. The argmax deliberately runs over every route including gated ones, so a route cannot escape its own gate by scoring at or below a clean sibling; the escape that remains one level up — trip a route's gate *and* sandbag that route so a clean one strictly outscores it — is real, ships documented, and is pinned by a characterisation test rather than claimed closed. **Wire**: `TraceConstraintResult` gains `string severity = 7`, and `Grade` gains `TraceChecksSummary trace_checks_summary = 11` — `winning_path`, `gate_failed`, `failed_gate_ids`, and one `TracePathResult` per declared route carrying that route's own score, never zeroed, so the max the component took is auditable from `grade.yaml` alone. A message rather than four scalars, because proto3 scalars have no presence and a `gate_failed` of `false` decoded from a runner predating the field is a gate silently opening; a summary the host cannot read **fails the grade parse** rather than being dropped. Both fields are written on every graded trial, matching their unconditionally-serialised sibling `trace_check_results`. **These are new keys on `extra="forbid"` runner-side models, so an engine of this release requires a runner image built from it for any pack declaring either** — `RegisterTrial` rejects an older image — while core's `extra="ignore"` means an older engine ignores them. `cache_debug` is the only shipped pack that declares them (see the entry below; scores on that pack are not comparable across the change) and no other pack changes verdict. Two adjacent limits are declared rather than closed: a `GradingKey` carries one `runner_field`, so a constraint kind written only inside a route falls outside the per-kind ledger's "populated ⇒ accounted" guarantee, which the manifest entry now says (**#772**); and `lot_ops_01` still passes an agent that double-posts the corrective action, a one-line application of this feature (**#773**) (#680)

- **grading**: **a `trace_checks` constraint can correlate arguments across matchers — it binds a value out of one event and requires, elsewhere in the same constraint, that another event's field equal or contain it.** Every predicate before this compared a field against a value written into the YAML, so *this call's id equals that call's id* had to be written as one constraint per concrete identifier, which does not generalise across task instances and silently stops covering whatever the author did not enumerate. A constraint's new optional **`bind`** declares the matcher whose events supply candidate values (`match`), the names extracted out of each (`values`: one `field` per name addressing `tool`, `text`, `result` or an `args.<dotted path>` on the kind `bind.match` selects, with an optional `pattern` narrowing it to exactly one regex capture), and **`on_unbound`**. `ValuePredicate` gains **`equals_binding`** and **`contains_binding`**, taking `TRACE_PREDICATE_OPERATORS` from fifteen to **seventeen**: both name a value rather than writing one and delegate to the same `operator.eq` / `contains` their literal siblings use, so **a bound constraint with exactly one candidate scores byte-identically to the same constraint with that value written out** — locked on score, verdict, message and matched positions. `bind` is a field of the **constraint** rather than of a matcher, a deliberate deviation from the issue's "a matcher can bind": the `require` tree becomes a function of an environment, so routes, gates, Kleene, quantifiers, `within`, `on_missing`, the weighted fold and the accounted-keys ledger all compose unchanged, and a reference reaching across a route boundary needs no rule of its own — it is the unbound-name load error. ## v0.2.2 (2026-06-03)

### Fixed

1. **Wheel resolver — relocated uv cache.** The Docker runner is provisioned from a host-resolved `tolokaforge` wheel; for a git-source install the `pip-cache` provider recovers the wheel `uv` built during `uv sync`. `_walk_pip_wheel_caches()` hard-coded `~/.cache/uv`, so when the cache was relocated (e.g. `astral-sh/setup-uv` sets `UV_CACHE_DIR` in CI) the wheel was missed and `tolokaforge run` failed at service start-up with `NoWheelError`. Cache *location* is now discovered via `uv cache dir` / `UV_CACHE_DIR` / `PIP_CACHE_DIR` (with the `~/.cache` defaults preserved); the uv-internal layout scan is unchanged, and `NoWheelError` now reports the caches it searched. (#27, #28)

## v0.2.1 (2026-05-29) — LLM Reasoning & Observability Overhaul

### Breaking Changes

1. **`ModelConfig.reasoning`** migrated from bare string to `ReasoningConfig` struct. YAML configs using `reasoning: "medium"` now raise `ValidationError` at load time — migrate to `reasoning: {mode: adaptive, effort_hint: medium}` or equivalent. See [`docs/CONFIG.md`](docs/CONFIG.md) § `reasoning:`.
2. **`GenerationResult.token_usage: dict`** removed — replaced by `GenerationResult.usage: Usage` (full Anthropic + OpenAI accounting incl. cache + reasoning tokens).
3. **`Metrics.tokens_input`** / **`Metrics.tokens_output`** removed — replaced by `Metrics.usage: Usage`. Aggregators expose `avg_<field>` / `total_<field>` per `Usage` field (e.g. `avg_reasoning_tokens`, `total_cache_read_input_tokens`).
4. **`Message.reasoning: str`** migrated to `Message.reasoning: StructuredReasoning | None` — preserves provider signatures + block types for replay.
5. **`tolokaforge.core.model_client`** / **`tolokaforge.core.model_policies`** modules deleted — every concept moved into `tolokaforge.core.llm.*`. Update imports accordingly.
6. **`in-process` runtime mode removed.** Docker is now the only supported runtime (`runtime: "docker"`). All tool execution is routed through the containerised executor service. Existing configs that specify `runtime: "in-process"` must be updated to `runtime: "docker"`.

### Fixed

1. **P1 / GPT-5.5 Decimal tool-call 500s** — `StrictSchema` now strips RE2-incompatible `pattern` + `format` keys and collapses Pydantic's `Decimal` `anyOf{number, string+pattern}` idiom to `{type: number}`. Four OTS domains that scored 0.000 on gpt55 now return valid tool calls.
2. **P2 / Qwen dict-map stringification** — new `qwen` preset wires `schema_sanitizer: strict` + `response_policy: array_dict_map` + `prompt_policy: dict_map_hints`. `qwen/*` and `qwen3*` now handle `Dict[str, T]` parameters correctly.
3. **P3 / Claude 4.7 ignores `reasoning: medium`** — new `anthropic_claude_4_7` preset emits canonical litellm `thinking={"type":"enabled","budget_tokens":N}` kwarg + drops `temperature` / `top_p` / `top_k` when thinking is active.
4. **P4 / Anthropic thinking blocks dropped across turns** — new `ReasoningCodec` abstraction captures full `{type, thinking, signature}` blocks on extraction and splices them back via `thinking_blocks` on assistant message dicts for interleaved-thinking replay.
5. **P5 / user-simulator prompt never persisted** — new `Trajectory.user_system_prompt` field captures the full simulator system prompt on first turn.
6. **P6 / effective tool schemas never persisted** — new `results/tools_schemas/<task_id>__<model_id>.json` sidecar dedup'd per `(task, model)` via filename.
7. **P7 / cache + reasoning token counters lost** — new `Usage` dataclass + `UsageExtractor` reads every normalised litellm field: `prompt_tokens`, `completion_tokens`, `reasoning_tokens`, `cached_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, plus `provider_raw` for forensics. OpenRouter-routed Anthropic caching now surfaces correctly — reads `prompt_tokens_details.cache_write_tokens` / `cache_read_tokens` as a fallback when top-level Anthropic fields are zero.
8. **P8 / no `cache_control` markers on Anthropic calls** — new `AnthropicEphemeralCache` automatically marks the last system-prompt content block + last tools entry with `cache_control: {type: ephemeral}` (5-minute TTL, Anthropic default).
9. **P9 / `reasoning: medium` abstraction leak** — new `ReasoningConfig(mode, budget_tokens, effort_hint, display)` provides explicit per-provider routing. Single in-repo legacy config migrated; external configs rebase in lockstep.
10. **P10 / no shared per-provider integration scaffolding** — new `tests/integration/llm/` with `Capability` enum + `ModelCertificate` registry; per-capability tests auto-skip with explanatory messages based on each model's declared certificate. See [`docs/ADD_NEW_MODEL.md`](docs/ADD_NEW_MODEL.md).

### Added

1. `tolokaforge/core/llm/` package with seven Protocol-driven policy modules:
   - `reasoning.py` / `reasoning_codec.py` — structured thinking-block extraction + replay
